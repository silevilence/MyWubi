# 专项排查 Windows 版 MyWubi 在飞书中无法输入

Status: 已完成

企业定制飞书 7.46.0.85 使用 32 位进程。旧版 MyWubi 只安装了 64 位输入法 DLL，32 位飞书无法加载它。补齐同版本的 32 位 DLL 和注册信息后，用户在原机的飞书搜索框确认可以正常选词上屏。

## 复现与验收

- 记录 Windows、飞书和 MyWubi 版本、实际复现的输入框及输入序列，用相同码表和编码在记事本做对照。
- 在飞书实际输入框中分别核对焦点、按键响应、候选显示和选词上屏，记录从哪一步开始失败。用草稿测试，无需发送消息。
- 修复后，在原输入框中连续输入两次，核对实际提交的文本、光标和选区，并回归任务栏搜索框。

## Comments

- 本次只登记用户反馈，原因留待专项排查。
- 2026-11-28 已在独立 Windows Sandbox（构建 26100）安装飞书 8.8.7，以 MyWubi 0.15.2 的本地构建 `7af859d` 复测。飞书主进程已加载 MyWubi DLL。在登录页「邮箱」输入框中，两次输入 `a` 并按空格均出现候选、成功上屏，UI Automation 读回「验收词验收词」。随后已清空测试文字。记事本与任务栏搜索框使用同一码表和选词键均能上屏。登录页未复现故障，聊天草稿需登录后另验。
- 2026-11-28 实机 Windows 构建 26200。企业飞书 EXE 的 PE Machine 为 `0x014c`（x86），原 MyWubi DLL 为 `0x8664`（x64）。32 位注册表视图缺少输入法 CLSID，独立 32 位 COM 客户端创建输入法时返回 `0x80040154`（类未注册）。故障发生在处理按键之前。
- 注册 x86 DLL 后，重复 COM 检查成功，并确认已经打开的企业飞书实际加载了 `im_engine_x86.dll`。用户在空搜索框中用自带五笔 86 码表输入两次 `a` 加空格，确认两次都有候选，结果为「工工」。上屏结果由用户读回，未单独测量飞书的选区坐标。此次实机验收使用搜索框，没有进入聊天或发送消息。测试结束后已恢复原先的搜狗五笔。

## 打包与回归

- 设置程序会将只有一种架构的旧安装显示为「状态异常」，可点击「修复安装」。在原沙盒中对完整目录执行 `regsvr32 /s im_engine.dll`、卸载、再安装。两个注册表视图依次指向各自的 DLL、同时清空、再指向各自的 DLL。
- 第一版 x86 构建依赖额外的 VC 运行库，干净沙盒加载失败。改为和 x64 相同的静态 CRT 后，沙盒通过安装和加载检查。最终沙盒构建的 SHA-256 为 x86 `4f1923b361ab833feb6f95949485a2718765597f3c18c47ea7654487a6699032`、x64 `5fa0aeaf3ff44f69241a204274eb3fd2ac5caa3cd81edbb188cdae972709a6d1`。实机飞书测试时使用的 x86 构建为 `7a419cbc26f65fe678f4c6524cd615db20894154e8e2ed0747265bbfd95c5c2f`。
- 复用本地五笔 86 码表，在沙盒的 32 位记事本、64 位记事本和任务栏搜索框分别键入两次 `a` 加空格。等待候选框出现后选词，每个宿主逐次读回「工」「工工」。两种记事本中，选词后选区均折叠在文字末端。
- 额外试验中，32 位 Windows PowerShell 临时创建的 WinForms 文本框只收到字母和空格，未观察到候选。该宿主的原因未定位。
- `cargo test --workspace --locked --offline` 通过 655 项，忽略 9 项。`cargo +1.96.0 test --target i686-pc-windows-msvc -p im_engine -p tip_manager --locked --offline` 通过 98 项，忽略 1 项。
