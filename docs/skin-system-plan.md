# MyWubi 皮肤系统规划

日期：2026-11-12。状态：已按用户确认的 ZIP 总—分 metadata、能力声明及 Windows 编辑器支持 Android 编辑要求纳入 ROADMAP，并完成本轮规划审核意见修订；所有功能任务仍未实施。本文同步说明与 AK 自定义键盘及 SI 快捷输入的组合边界。

## 1. 推荐方向

做一套适合长期打字的皮肤系统：默认清楚、紧凑，普通用户可以直接选用，高级用户可以调整和分享。借鉴小狼毫的结构化参数，以及搜狗、QQ 的浏览、预览、应用、制作流程。

建议先交付参数化皮肤，再交付静态图片皮肤。Windows 重点是候选框；Android 重点是键盘和候选栏。两端共享皮肤身份、语义配色和文件规则，各自定义布局、字体与交互状态。跨端一致指视觉语言一致，不要求逐像素一致。

Windows 设置程序提供同时面向 Windows 与 Android 的皮肤编辑器，可创建单平台包或双平台包；编辑目标与当前设备的应用目标分开。Android 端首版负责选择、预览、应用和分享，不要求具备完整作者编辑器。

外观、键盘布局、编码映射是独立组件，允许同包分发或从已安装包中组合选择。纯外观只控制视觉；用户显式启用布局组件后，才改变键位和手势。支持九键、十四键、分体、错列及至少八向滑动；方向可合并为同一动作。这些能力由 AK 系列实现，不要求先完成图片皮肤。

本次产物是规划和概念预览，不包括运行时实现、竞品安装或真实设备验收。

## 3. 当前代码基线

| 位置 | 已有能力 | 规划需要补足 |
| --- | --- | --- |
| `core_engine/src/config.rs`：`Appearance`、`DesktopOptions` | Windows 外观含字号、主色、背景色、高亮色；字号单位为 pt | 命名皮肤、明暗变体、语义颜色、平台参数、兼容迁移 |
| `windows/settings/src/panels/appearance.rs` | 三种颜色、8～32 字号滑块、egui 手绘简易预览 | 真实布局预览、皮肤列表、自定义副本、导入导出、撤销草稿 |
| `windows/im_engine/src/candidate_data.rs` | `ThemeSnapshot` 随候选数据传递 | 独立外观版本和完整解析结果 |
| `windows/im_engine/src/candidate_layout.rs` | 系统文字度量、横排放不下时转竖排；绘制与点击共享布局 | 显式布局偏好、文字/序号/提示分别样式化、稳定尺寸、统一状态样例 |
| `windows/im_engine/src/candidate_renderer.rs` | 缓存场景、滚动、屏幕避让、分层窗口输出 | 参数化边框/圆角/阴影、皮肤版本缓存失效 |
| `windows/text_render/src/lib.rs` | DirectWrite 字形与 Direct2D 软件绘制，支持彩色字体 | 当前 DC target 忽略 alpha，输出 alpha 全设 255；透明圆角与阴影需要新的合成处理 |
| `windows/im_engine/src/reload.rs` | 配置/资源监听与快照发布，部分加载失败保留旧快照 | 仅改外观时不触发整套引擎资源重建；皮肤资源依赖和失败恢复 |
| `android/.../Theme.kt`、`Keyboard.kt`、`KeyTouch.kt` | Compose 系统明暗配色、键盘/候选/按键预览 | 将分散样式接入皮肤；选择、预览、导入和平台专属参数 |

技术基线以当前代码为准：Windows 保持现有无焦点分层窗口，复用 DirectWrite/Direct2D 与 GDI 输出。皮肤任务不需要引入 WebView、egui DLL 运行环境或更换整个渲染架构。

## 4. 怎么设计才好用

### 默认视觉

- 默认沿用 Android 已有的墨绿方向，让两端形成统一识别；浅色与深色成对设计。
- 候选正文最突出，选中项有独立前景/底色；序号、编码提示、模式说明次之，不能全部染成主色。
- 编码行、候选区、状态/翻页区结构清楚。状态文字不混入编码或候选正文；已有表达式、模型状态和不可用模式都能完整显示。
- Windows 默认紧凑横排，提供竖排阅读模式。空间不足时有明确的换行/转竖排/滚动规则；皮肤不能擅自改变候选数量、排序、选词键或上屏行为。
- 视觉偏好和使用偏好分开：换皮肤默认保留用户字号、布局偏好、提示开关和 Android 键盘高度。另设“采用皮肤推荐排版”显式重置。
- 不为换肤增加打字时的动画；选中反馈立即发生。装饰只出现在不会遮挡文字、提示、按键标签的位置。

### 内置方案

| 方案 | 外观 | 使用场景 |
| --- | --- | --- |
| 墨绿 | 浅底深字、墨绿选中底；配套深色变体 | 默认，承接 Android 已有视觉 |
| 素简 | 中性灰、细边框、低装饰 | 办公、编辑器、长时间输入 |
| 高对比 | 不透明背景、清晰选中边界、较强文字对比 | 阅读辨识，系统高对比时优先采用 |

紧凑/舒适密度是排版选择，不复制成一批只有间距不同的皮肤。大字也属于用户偏好，可以叠加到任何方案。

建议起始参数：Windows 正文 14 pt，提示不低于 11 pt；外框圆角 8 DIP，选中项 4 DIP，内边距横向 8 / 纵向 6 DIP，边框 1 DIP。Android 文字用 sp、间距用 dp，不照搬 Windows 尺寸。以上是打样起点，最终以实际字体度量、缩放和触摸验收确定。

墨绿起始色板：浅色背景 `#F4F7F5`、正文 `#192C27`、次要文字 `#52635B`、选中底 `#245D51`、选中字 `#FFFFFF`；深色背景 `#191F1D`、正文 `#E1E8E4`、次要文字 `#AFBEB6`、选中底 `#9CD3C1`、选中字 `#00382C`。内置方案正文/提示文字以 4.5:1 为最低对比度验收目标；透明背景、图片和禁用态需单独检查。自定义低对比颜色提示问题并允许恢复，不偷偷替换用户颜色。

### Windows 的皮肤页面

1. 顶部显示当前皮肤与“跟随系统 / 浅色 / 深色”。
2. 皮肤列表用真实样例缩略图，清楚标注已应用、当前草稿和支持平台。
3. 选中皮肤后立即更新页面内预览；提供“普通形码 / 长词和反查 / 表情 / 模式与状态”样例。
4. 常用调整只放字号、横竖排、紧凑程度；展开“高级”才显示语义颜色、字体、边距、圆角等。
5. 编辑内置皮肤产生“自定义副本”。恢复默认与丢弃修改作用清晰。
6. 点击“应用皮肤”才保存并发布；取消保留原样。导入仅加入本地列表，不自动启用。

这里的“实时预览”默认只影响设置页。未来若提供真实输入试用，要有明确的开始/结束与恢复机制；首版不需要在每次拖动滑块时写配置。

### Android 的对应体验

- 皮肤详情同时展示候选栏、字母键盘、数字符号、空格/回车功能键、按下状态与按键气泡。
- 设置页面可以保持原生 Material 风格；用户皮肤作用于输入界面，不必把整套设置应用也装饰化。
- 使用系统文件选择器导入、系统分享导出。仅含 Windows 参数的包标为不支持 Android，不静默套用半套样式。
- 按键触摸范围、长按取消、滑动替代字符、删除手势、密码场景和 TalkBack 语义不受装饰影响。
- 文字放大时允许调整键盘布局/高度；窄屏触摸尺寸无法达到目标的情况应明确记录，不能仅凭皮肤截图宣布通过。

## 5. 皮肤包、能力声明与跨端编辑

### ZIP 容器与总—分 metadata

采用标准 ZIP 容器，建议扩展名 `.mywubi-skin`，同时接受具有有效根 metadata 的 `.zip`。总—分 metadata 采用 TOML，与项目现有配置工具链保持一致；文件名和字段最终在 SK-02 固定。参数版和图片版沿用同一容器。

```text
metadata.toml                 # 总：包身份、版本、能力、平台入口、共享默认值和资源索引
shared/
  assets/                     # 可被两个平台引用的图片，只存一份
windows/
  metadata.toml               # 分：Windows 公共能力、组件目录及外观参数/入口
  assets/                     # 可选，Windows 专用资源
android/
  metadata.toml               # 分：Android 公共能力及组件目录
  appearance.toml             # 可选，外观组件及其能力/变体/参数
  layouts/                    # 可选，各布局的键位、状态、方向与动作声明
  mappings/                   # 可选，各编码映射的字符组及适用条件
  assets/                     # 可选，Android 专用资源
```

- 支持 Windows 单平台、Android 单平台、双平台包。由总 metadata 显式声明平台入口，不靠扫描目录推断；每个入口必须指向对应子目录中的有效分 metadata。
- 总 metadata 管理唯一的包 ID、名称、作者、包版本、许可证、格式版本、共享语义色板/默认值和共享资源索引。分 metadata 引用总信息，不复制包身份，记录平台公共能力及组件目录。每个组件具有稳定 ID/版本、种类、必需/可选能力及依赖；外观记录明暗与推荐排版，布局/映射记录动作和编码规则。参数可内联或指向包内文件，正式字段在 SK-02 固定。
- 从首版支持未知组件目录项的跳过与无损保留。只含布局的包可采用内置外观，不因缺少自带色板被误判为损坏；一个平台可包含多套外观、布局和映射。
- 新格式颜色采用明确的 `#RRGGBB` / `#RRGGBBAA`；旧 `0xAARRGGBB` 显式转换，不直接重解释字节。
- 资源通过 ID 引用；共享索引路径相对 ZIP 根，平台索引路径相对所属平台目录。平台可引用共享资源或本平台资源，不借助 `../` 访问其他平台私有目录。不使用本机绝对路径或远程资源 URL。
- 共享资源 ID 与平台资源 ID 使用独立命名空间，不依赖同名遮蔽。修改共享图片前显示受影响的两个平台；支持“复制为本平台资源”，不因编辑 Windows 皮肤意外改变 Android。
- 支持 `light` / `dark`，也支持明确声明单变体。缺少目标变体时保留原变体并提示，不自动反相。

### 能力声明与兼容规则

能力必须描述具体范围与版本，例如 Windows 候选框、Android 候选栏/键盘/按键气泡、参数配色、静态图片、九宫格；这些是能力类别示意，正式键名在 SK-02 固定。平台覆盖范围与渲染能力分开声明，不能仅写一个 `supports_android = true`。

SK-02 从首版固定“容器 → 平台 → 组件”三级能力边界。根 metadata 声明容器能力；平台入口只声明所有组件共同需要的公共基础能力；外观、布局、映射各自声明 `required` / `optional` 及组件依赖。九键、八向手势、分组检索和图片等专用能力必须放在相关组件，不能错误提升到平台公共层。AK-02 只扩展组件种类和字段，不另造一套拒绝规则。

先判断容器与平台公共能力，再判断所选组件及其依赖闭包。仅依赖失败的组件被禁用，互不依赖的外观仍可选用。不声称支持连根格式都不能理解的更老客户端；根格式不兼容仍拒绝整个包。

| 情况 | 客户端应用 | Windows 编辑器 |
| --- | --- | --- |
| 未声明当前平台 | 不允许应用，明确显示不支持该平台 | 可以编辑包中另一个受支持的平台 |
| 缺容器必需能力或根格式不兼容 | 拒绝整个包 | 不覆盖源包，报告原因 |
| 当前平台缺公共必需能力 | 禁用该平台，其他平台不受影响 | 受影响平台只读保留 |
| 所选组件缺必需能力、依赖缺失或版本不兼容 | 禁用该组件及依赖它的组件，独立可用外观仍可选择 | 受影响组件只读，不擅自降级改写 |
| 组件种类未知 | 不执行该组件；可继续使用独立的已知组件 | 保留其声明和资源，可编辑其他组件 |
| 缺可选能力 | 只按所属范围声明的回退降级并提示 | 标明预览限制，保留原声明与数据 |
| 另一平台需要较新的能力 | 不妨碍当前平台使用已支持的内容 | 另一平台只读保留；可编辑已支持平台并无损再导出 |
| 包结构损坏或非法资源路径 | 拒绝整个包，不部分激活 | 不覆盖源包，报告具体错误 |

能力声明需要与实际字段和资源引用校验，不能通过漏声明绕过检查。未知组件及合法扩展数据必须能在编辑后保留；无法分析其资源依赖时保留相应共享资源，不自动当成未使用素材删除。无法无损保存时禁止覆盖或导出修改版，不能悄悄丢弃另一平台或另一组件。

固定验收例：同包包含普通 Android 外观与需要字符组检索的十四键布局，只支持外观的客户端可以选择该外观，但明确禁用十四键；不能把字符组当成字符串提交，也不能因为十四键不可用而拒绝独立外观。

### 参数归属与覆盖

- 共享语义色：背景、边框、正文、序号、提示、编码、选中背景/正文/提示、禁用态、状态提示。
- Windows 分 metadata：字体族/回退、推荐字号、横竖排、间距、最大宽度、边框、圆角、阴影。
- Android 外观组件：候选栏、键帽、功能键、按下态、气泡及各状态配色，不改变键位、手势或输入动作。Android 布局组件可以在显式启用后改变排列与动作绑定；映射组件定义字符组，由核心解释。两者均不能执行脚本或任意平台命令。
- 用户偏好：字号、布局、密度、Android 键盘高度等独立保存，不属于分发包默认内容。导出不捆绑个人词库、本机路径或其他个人数据。

有效值的覆盖顺序：内置默认 → 总 metadata 共享默认/所选明暗色板 → 分 metadata 平台公共默认 → 所选外观组件/变体 → 用户明确覆盖 → 系统高对比/可访问性约束。布局与映射独立校验，不参与外观字段合并。集合合并、缺失字段、显式清空与类型冲突的规则在 SK-02 固定；不使用含糊的递归合并。系统约束不回写原皮肤。

保持平台 UI 配置独立。纯 Rust 公共模块承载包结构、能力判定、字段校验与有效值解析；Windows 编辑器、Windows 运行端和 Android 经共享接口复用同一契约。系统主题检测、文件选择器、图片解码与绘制由壳层承担。扩展 `config.toml` 时同步 Rust 结构和双端设置读写，不把 Windows 布局混入共享输入行为。

### 有效键盘组合与资源生命周期

AK-18 将外观、布局、映射和资源解析成一个有效键盘组合，AK-19 在十四键交付前提供启用、保存与恢复。跨包选用通过本地包管理器绑定，不允许 metadata 用文件路径跨越包目录。

- 组合记录包 ID/版本、组件 ID/版本、资源摘要及组合 revision；布局引用的每个分组和动作都必须存在，适用模式/字符集、必要操作与有效触摸区域均须匹配。
- 样式以普通键、功能键、选中项、方向标签、气泡等语义角色匹配。缺少可选角色样式可使用声明的内置回退；固定键位图片必须声明适用布局，不能把 26 键底图静默拉成十四键。没有合法回退的必需素材或映射缺失时拒绝组合。图片尚未实现时用能力/样式契约样例检查组合规则，不要求提前完成图片解码和渲染。
- 全部组件及资源准备成功才原子发布；任何失败保留完整旧组合，不能出现新布局配旧映射。已保存选择与当前活动组合分别报告，更新中断可恢复上一个完整有效版本。
- 活动会话、待生效组合、在途手势及候选都引用固定版本，最后一个引用释放前不回收旧资源；从新包里删除旧分组不使当前会话的输入被重新解释。
- 仅改颜色保留组序列；改变触摸几何须等松手或取消旧手势；不兼容映射等当前输入结束后生效，或由用户显式取消当前输入再切换。
- 密码使用内置确定字符键盘并关闭输入预览和歧义候选；数字/电话使用确定数字布局。英文/网址默认确定字符布局，只有已验证精确输入能力的自定义布局可选择。始终有独立于自定义键位的全键/恢复入口；离开受限输入框后恢复原兼容选择。
- AK-18 先以共享校验器与运行端契约样例验收，实际编辑器一致性由 AK-14 验收；AK-19 先用 26 键与字符组布局契约样例交付单活动组合、重启保留和失败恢复，AK-09 再用正式十四键模板验收，AK-13 再扩展按模式记忆与复杂切换。十四键不等待九键拼音才获得启用和密码回退能力。

### 八向动作与删除键例外

支持至少八方向独立绑定或合并。布局默认可由按键覆盖/显式禁用；最终每个方向只属于一个动作组。左上、上、右上可以共同触发宽上滑，未绑定方向不自动转为其他动作。Windows 编辑器提供八向方向盘及轨迹模拟，Android 真机验证阈值、防抖和可达性。

普通键的点击、长按、滑动互斥，松手最多派发一个动作。已进入滑动后回中心取消，松手不得补发点击。这是明确的新取消行为，不要求保留旧版回中心后可能触发点击的结果。

删除键保留独立状态机：长按可连续退格；上划进入待清空后停止重复；松手至多清空一次；下滑撤销待清空后可按原规则恢复重复。取消清空不撤销已发生的退格。系统取消、失焦、重建等立即停止，不能补发清空或点击。删除专用行为不能同时挂上另一套通用八向动作；如作者选择普通动作键，则不能保留隐含的删除状态机。TalkBack 同样区分退格、清空和普通方向操作。

### 字符组与 SI 快捷输入的边界

首版不对未消歧组生成日期候选。只有每个位置都已由用户输入或显式消歧确定为字母，且完整命中 SI 的可生效规则时，才进入 SI 候选生成。词典仅剩一个词或剪枝仅剩一个编码，不自动把原始组视为已确定。

组序列仍可能匹配有效快捷编码或其真前缀时，禁止提前唯一上屏和满码顶字，并按位置计数允许继续到 SI 的 32 字母上限；不再兼容前缀、规则停用/不兼容后退出保护。明确选普通候选或取消仍可结束本轮。未确定组的回车/原始提交只提示先消歧，不能输出组标记或擅自选字母；确定后的原码提交保持 SI 原规则。

首次确定完整命中时按 SI-07 取一次时间快照；歧义输入、预判、翻页和纯外观更新不取时。显式消歧、退格、映射/规则更新使旧查询失效。普通/特殊/动态候选沿用 SI 的身份、位置、去重和分页，不能在合并后重新按字词去重。临时拼音、英文、密码和专用查询不触发日期规则。

AK-01/06/08 先固定此边界和契约样例；AK-20 依赖 SI-09 做真实联调，AK-09 的独立十四键交付不因此依赖 SI。完整自定义键盘验收 AK-17 与两组联合验收 SK-20 必须经过 AK-20。固定例子：规则为 jjad 时，输入 {j,k}、j、a、d 仍无动态项且不取时；显式将首位确定为 j 才出现日期并取时一次，翻页跨秒不重新取时。

### Windows 编辑器中的 Android 编辑

编辑器提供“包信息 / 共享资源 / Windows / Android”入口，可以创建、添加、编辑或显式移除一个平台，自动同步能力声明和资源引用。默认只编辑选中平台，平台切换保留各自未保存草稿。共享色板和图片变更显示影响范围；保存失败保留草稿和原包。

Android 外观编辑覆盖候选栏、普通键/功能键、按下/禁用态、气泡、明暗变体、圆角与间距；图片阶段增加图片选择、内容留白和九宫格配置。AK-14/15 进一步提供布局、映射、八向动作和方向合并编辑，复用 AK-18 的组合校验。Windows 编辑器不能因为本机不能应用 Android 皮肤，就拒绝打开 Android 单平台包。

预览分为两类：Windows 复用实际候选布局与绘制；Windows 内的 Android 预览复用同一参数解析规则、状态样例与尺寸契约，提供屏宽、横竖屏、字体缩放和按键状态预览。Windows 不运行真实 Android Compose，系统字体、shaping、Insets 与设备缩放可能有差异，界面明确标为“Android 示意预览”。无需连接手机也能完成编辑和导出；最终验收必须将导出的原包在 Android 原生预览与真实键盘中核对，不能要求或声称跨平台像素完全相同。

编辑往返要求：打开双平台包 → 只改 Windows → 导出 → Android 分 metadata 语义和未修改资源内容保持；反向也成立。未知但合法的扩展字段保留，未修改的资源用摘要核对。ZIP 压缩顺序或时间戳变化不视为内容变化。外部文件修改与保存冲突应提示，不覆盖用户的新版本。

## 6. 加载、兼容与资源

- 旧配置未选择皮肤时继续呈现旧外观，不自动换成墨绿。首次迁移可生成“当前自定义外观”副本，保留四个旧字段；旧 ARGB 的透明度因旧渲染未生效，不在迁移时突然启用。
- 皮肤校验成功后才激活。导入到暂存位置，验证后发布到独立版本目录；同名不同 ID 不互相覆盖，同 ID 新版本保留可回退版本。
- ZIP 必须限制文件数、展开后总量、单图像素量，并拒绝绝对路径、父目录跳转、链接条目和大小写路径冲突。包级检查覆盖全部目录；运行端只解析和解码本平台实际需要的资源，Windows 编辑器保留另一平台与合法扩展资源。不执行脚本、加载插件或自动联网。
- 建议初始限额：压缩包 5 MiB、展开 20 MiB、64 个文件、单图 2048×2048、解码资源合计 32 MiB；在图片阶段用实际样本确认后固定为契约。限制是导入策略，不代表 DLL 必须常驻全部资源。
- 字体优先使用已安装字体和系统回退；首版不打包或安装字体，不破坏 Emoji/组合字符的整串 shaping。
- 运行期使用不可变的已解析皮肤快照，逐键路径不读文件、不解压、不解码图片。Windows 的图形对象继续限定在渲染线程。
- 纯外观更新使用独立 revision，不触发词库、模型或输入会话重建；更新期间保留当前编码、候选身份和上屏协议。
- 明暗切换、DPI 变化、字体与皮肤更新均纳入缓存失效。有效皮肤损坏时保留上一次可用状态；冷启动无可用资源时回退内置方案并在设置页报告原因。
- 多个宿主中的 DLL 需要接收同一保存结果；资源删除不能破坏正在使用的版本。跨进程通知沿用项目可行机制，必须实测已打开宿主与新启动宿主。
