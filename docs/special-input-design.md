# 特殊输入实施契约与界面设计（SI-01）

2026-11-12 固定，依据 ROADMAP 的 SI 共同规则。此文交付设计和验收基线，不代表新输入功能已经实现。任务按依赖推进，运行时/界面/真实宿主结果分别验收。

## 1. 可执行验收数据

`validation/special-input/cases.json` 保存 SI-C01～SI-C11 的输入、预期文本、来源、位置和生命周期结果。数字均为用户看到的 1 基位置，接口索引由适配层换算。合并样例中的基础序列已经完成主表排序和普通/特殊去重；C05 专门验证特殊与动态去重。

| 动作 | 消费/宿主行为 | 候选与版本 |
| --- | --- | --- |
| 有效快捷前缀输入 | 消费；更新原码预编辑；不自动上屏 | 修改编码使旧候选失效 |
| 完整快捷匹配 | 消费；显示原码及候选；不自动上屏 | 首次创建时间快照，输出按 C01～C06 |
| 翻页/窗口读取 | 翻页消费、读取无副作用；不写正文 | 复用时间与候选身份；展示版本按既有接口变化 |
| 数字/点击选择 | 提交对应原始文本；来源提示不提交 | 动态项不写用户词库；普通同文项保留原语义 |
| 空格/回车/Esc | 分别当前页首选/原始编码/取消 | 结束查询；空缓冲行为沿用平台协议 |
| 退格再补回/资源重载 | 原规则处置预编辑，不重放提交 | 旧查询 ID 失效；重新匹配时取新时间 |
| 可重试且确定未写入 | 保留既有允许重试的会话 | 不重新取时；不改变 Windows 主模式恢复策略 |
| 部分写入/结果未知 | 不自动重放 | 进入原恢复流程，不伪造成功 |
| 专用查询编辑 | 仅修改本地查询，不写宿主 | 主表组词与字面别名模式明确分开 |

普通与动态同文保留两项；特殊与动态同文删特殊后插入；两条动态规则同文保留不同身份。同规范编码同位置是配置错误，包括停用项。规则字母编码和格式语法、冲突暂停、时间边界均以 ROADMAP 的共同规则为准，前端不复制另一套判定。

## 2. Windows 设置

在现有主导航增加“特殊输入”，将常规页原表情设置迁入。页内可用宽度 ≥760 逻辑像素时采用 208～240 宽的列表和剩余详情区域；更窄时显示列表/详情单层导航，返回列表保持选中项目、搜索和滚动。使用现有 egui 字体、颜色、控件和底部统一保存区，不引入皮肤编辑能力。

```text
特殊输入                                  [有未保存修改]
搜索类别或编码
特殊码表                 数学符号
  Emoji   追加·检索       普通输入时追加 [开]
  颜文字  未启用         专用检索       [开]
  假名    仅检索         当前资源 [内置数学符号 v1 ▾]
  数学符号 追加·检索     [导入资源] [使用内置资源]
  标点                   试用 [主码表组词 | 直接输入别名]
  其他符号               查询… [查找] 结果/名称/缺字回退
快捷输入                 > 版本、来源与许可
  jjad    2 条·可用
  [新增编码]
                         [保存设置] [重新加载/放弃草稿]
```

类别是一行、活动资源是一份；导入新的资源版本不会增加第二个可启用的类别。列表文字摘要由用途、资源可用性组成，不能仅靠颜色。资源检验、导入在后台执行；导入后选择是草稿，保存才应用，失败保留原选择。选中另一个项目不触发保存或弹窗。

快捷详情按编码管理。顶端显示规范小写编码、启用意图及当前可用原因；表格为“启用 / 全局位置 / 类型 / 格式 / 示例输出 / 复制 / 删除”。底部预览显示活动主表与资源版本、固定示例时间、目标与实际位置、来源、有效页容量。配置容量 10 而动态命中采用 9 时就地说明。字段错误阻止保存并定位首个错误；环境冲突是可保存的暂停，不把启用开关改成关闭。

首次打开默认不自动执行查询。试用和格式预览不操作当前输入会话、不向宿主发送文本。离开设置且有修改时提供保存/放弃/继续编辑；切项目和返回列表保留草稿。键盘 Tab 遍历列表、详情、底部动作，Enter 激活焦点控件，Esc 先关闭弹层再返回，不越过未保存处理。

## 3. Android 设置

提供“特殊输入”入口，将原常用页长表情区移入。可用内容宽度 <600 dp 时采用列表 → 类别/编码详情 → 必要的格式帮助；≥600 dp 采用 240 dp 列表和详情双栏。宽度由实际窗口决定，横屏不强制双栏。系统返回先关闭格式帮助/资源选择，再回列表；列表返回上层才进入未保存处理。

列表的分组、顺序、摘要与 Windows 一致，手机详情用纵向分段而非压缩桌面表格。每条日期格式显示位置、格式、预览和编辑入口；编辑页保留新增/复制/删除及启停。控件触摸区至少 48 dp，列表项至少 56 dp；大字体下允许增高、换行，不固定文本高度。保存区域避让系统栏和软键盘，表单可滚动到字段错误。

ViewModel 保存草稿、所选项目、查询方式和列表滚动；旋转不重新导入或重置编辑。进程被系统终止时沿用已有配置恢复边界，不声称未持久化草稿永久保存。TalkBack 读出类别名、用途、不可用原因，错误更新使用适当状态提示；同文候选读出来源，不将来源写入宿主。

## 4. 运行时检索

Windows 辅助菜单及 Android 键盘工具入口列出全部类别；禁用/资源不可用项显示原因，不能点击后静默无结果。进入后显示类别名和两种查询方式。初始为主码表组词；查询非空时方式切换不可执行，提示先清空。退出返回进入前模式。

字面别名方式直接收集查询字符，`shi` 和 `SHI` 搜索相同别名；编辑时数字也是文本，结果时才选词。Tab/查找触发检索，查询与确认关键词均不写宿主；结果中修改返回查询编辑，取消退出，不自动提交首项。普通主表 `shi` 缺失也必须能完成 C10。

## 5. 性能基线和预先固定门槛

基线提交、主机系统、编译器、制品/资源 SHA-256 和三次原始运行见 `validation/special-input/baseline-windows.json`；内存采样见 `baseline-memory.json`。Intel Core Ultra 7 165U，Release、离线复用本地资源。每次新进程先加载资源（保留 OS 文件缓存，不声称冷盘），查询预热 20 次再测 200 次；五字符输入预热 20 次再测 1000 次。记录 nearest-rank p50/p95/p99，三次分别保存，不删除慢样本。

此次旧路径测量：五字符输入 p95 为 1.8～4.9 μs；Emoji 加载约 50.6～54.4 ms，搜索 p95 约 1.81～2.20 ms；颜文字加载约 143.3～149.3 ms，搜索 p95 约 0.79～0.94 ms。采样进程峰值工作集 46,071,808 字节。测量范围不含 JNI、绘制或实际宿主。

Android 无已连接设备，不启动新模拟器占用桌面。既有 API 34 x86_64 指纹和 JNI 样本见 `validation/expressions/2026-11-09/android-api34/expression-benchmark.json`：启用表情运行时构建 1084.9 ms、JNI 输入/确认/候选 p95 73.8 ms；这是历史参考，不能充当当前制品或真机结果。Android 和新路径采用下列绝对门槛，SI-15～SI-17 必须补测，缺设备不标完成。

| 指标与范围 | Windows 本机 Release | Android API 34 x86_64 参考环境及 ARM64 真机 |
| --- | --- | --- |
| 全关闭的旧五字符核心路径 | p95 ≤10 μs、p99 ≤20 μs | JNI 完整五字符轮次 p95 ≤25 ms、p99 ≤50 ms |
| 1024 条未命中规则：五字符核心轮次 | p95 ≤100 μs、p99 ≤200 μs | JNI 轮次 p95 ≤35 ms、p99 ≤60 ms |
| 多类别命中/同码 32 条规则：搜索或候选合并 | p95 ≤10 ms、p99 ≤20 ms | JNI 含窗口查询 p95 ≤150 ms、p99 ≤250 ms |
| 全部内置资源及规则运行时构建 | ≤2 s（OS 缓存可用） | ≤3 s（相同缓存条件） |
| 独立核心测量进程峰值工作集 / 应用 PSS | ≤128 MiB | 完整输入法应用 PSS ≤256 MiB |
| 按键/触摸到新候选实际呈现（排除模型预测） | p95 ≤100 ms、p99 ≤150 ms | p95 ≤200 ms、p99 ≤300 ms |

输入集和未来压力规模固定在 `workloads.json`：禁用、1024 条未命中、六类别命中、单码 32 格式；其 SHA-256 记录在清单。新增类别压力集使用每类别 1024 条合成条目，正式资源完成后另外记录正式全集，不替换合成集。旧制品只能测旧路径，绝对门槛不要求旧制品识别新配置。

每项至少三轮：热指标比较三轮各自的 p95/p99，均不得超限；加载/内存记录三轮最大值。采集系统负载、构建和资源摘要；后台干扰可记录并整组复测一次，不挑选单个样本或修改门槛。无法复现时保留失败。设备差异单列，不以模拟器通过推定真机通过。

## 6. 验收与交付边界

SI-01 的快速检查：JSON 结构及 C01～C06 独立位置演算；基线工具 Release 实际运行；文档流程覆盖空/加载/失败/草稿/冲突/退出；逐项检查门槛有单位和环境。此阶段只有设计及旧路径基线，不勾选 SI-05～SI-17。后续实现测试须直接消费固定样例，而非先从实现生成期望值。

最终集中验收前先构建、复用本地资源和整理用例；Windows 记事本/浏览器及 Android 真实宿主一次集中验证，结束后及时关闭测试进程。缺真机、宽屏、TalkBack 或最终 TSF 证据，相关任务继续保持未完成。
