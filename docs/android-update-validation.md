# Android 应用更新验收

任务来源：ROADMAP.md AU-01～AU-04。日期：2026-11-03。

## AU-01

- 发布流程从签名 APK 的 aapt badging 提取包名、版本号、最低 SDK 和 ABI，生成
  `android-update.json`，与 APK 一起先上传草稿，再公开 Release。
- 检查仅请求固定 GitHub Release API 与该正式 Release 下的元数据；网络任务运行在
  IO 协程，不接收输入文本、编辑器或引擎句柄。仅打开键盘时触发，不在逐键路径调用。
- 成功检查间隔 24 小时，失败从 15 分钟指数退避至 24 小时；手动检查可绕过时间限制，
  但不能创建并行检查。失败保留已知版本，设置页明确显示失败；成功无更新清除缓存。
- API 34 x86_64 模拟器 `AppUpdateTest` 4 项通过：新/同/旧版本、SDK/ABI、草稿/预发布、
  非公开/缺失/异常元数据、退避、慢请求不阻塞主线程、并发去重、失败重试和缓存重建。
- Python 发布脚本测试 4 项通过。APK 构建通过。真实 GitHub 发布未执行；下一次签名
  发布才会提供此元数据，旧版本无元数据时主动检查报告失败，不报告“最新”。

## 设备范围

当前仅连接 API 34 x86_64 模拟器；没有可用 ARM64 真机。未测设备与系统行为不以构建
成功代替。后续各阶段结果记录在此文件。

## AU-02

- `KeyboardIdleTest` 2 项主机测试通过：1.8 秒稳定间隔，连续直输、触摸长按、
  预编辑、候选交互、空临时会话均阻止提示。
- API 34 `UpdateToolbarTest` 通过：静态提示点、触摸时隐藏但设置按钮仍能点击、
  英文/数字/密码呈现、候选优先、更新清除。真实 `ExternalHostTest` 2 项通过，
  覆盖 g/g/l/l → 王、选词、大小写、长按退格及隐藏后取消重复。
- 修正旧测试在上屏后仍寻找“收起”的断言，改为验证候选区域随提交消失。
- 服务在新输入框、显示/隐藏和重建时重置静置间隔，销毁时移除计时器和订阅。
  检查结果只改变缓存/可用版本，不改变输入状态；候选列表存在时不给设置提示占位。

## AU-03

- 下载独立于输入服务，仅设置页的用户操作可启动；展示进度、取消中、取消、失败与重试。
  完成后校验 SHA-256、包名、versionName/versionCode、最低 SDK、设备 ABI 和已安装签名。
  API 28+ 支持系统已验证的前向签名轮换历史；多签名和较旧系统使用相同签名集合。
- 安装前再次复核文件，使用不导出的 FileProvider 临时授予精确 APK URI 的只读访问。
  用户明确确认后才进入系统授权/安装；授权返回不自动安装，仍需再次点击。
- `UpdateDownloadTest` 3 项通过：取消清理与进程中断、失败重试/去重、已下载恢复及篡改、
  校验和/包名/版本/降级/系统/错误签名拒绝。发现并修复协程取消后未发布最终状态的问题。
- API 34 系统安装器验证拒绝授权→重试授权→取消安装→Activity 重建，安装包仍可恢复。
  撤销 REQUEST_INSTALL_PACKAGES 时 Android 会杀死应用，因此测试脚本在 instrumentation
  启动前复位权限；这不是应用崩溃或校验失败。
- `android/test-updates.ps1 -Serial emulator-5554 -InstallUpgrade` 通过：10 项专项测试，
  随后用户确认路径从 debug 签名 versionCode 4 覆盖到 5；安装导致旧测试进程结束，
  独立的升级后测试 1 项通过。版本名称均为 0.5.1，仅 versionCode 在本地测试构建中递增。
- 升级前主动导入完整示例主表与辅助表，记录已有配置、码表包与用户词库共 36 个
  引擎数据文件；升级后逐文件 SHA-256 相同，旧下载文件清理、过期提示清除。
- 此次使用本地生成的同一 debug 签名制品、受控检查/传输测试替身和真实系统安装器；
  不声称已经从生产 GitHub Release 下载升级，也没有使用/更改生产签名密钥或发布版本。
