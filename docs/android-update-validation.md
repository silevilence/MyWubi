# Android 应用更新验收

任务来源：ROADMAP.md AU-01～AU-04。日期：2026-11-03。

## AU-01

- 发布流程从签名 APK 的 aapt badging 提取包名、版本号、最低 SDK 和 ABI，生成
  `android-update.json`，与 APK 一起先上传草稿，再公开 Release。
- 检查仅请求固定 GitHub Release API 与该正式 Release 下的元数据；网络任务运行在
  IO 协程，不接收输入文本、编辑器或引擎句柄。仅打开键盘时触发，不在逐键路径调用。
- 成功检查间隔 24 小时，失败从 15 分钟指数退避至 24 小时；手动检查可绕过时间限制，
  但不能创建并行检查。失败保留已知版本，设置页明确显示失败；成功无更新清除缓存。
- API 34 x86_64 模拟器 `AppUpdateTest` 4 项通过：新/同/旧版本、SDK/ABI、草稿/预发布、
  非公开/缺失/异常元数据、退避、慢请求不阻塞主线程、并发去重、失败重试和缓存重建。
- Python 发布脚本测试 4 项通过。APK 构建通过。真实 GitHub 发布未执行；下一次签名
  发布才会提供此元数据，旧版本无元数据时主动检查报告失败，不报告“最新”。

## 设备范围

当前仅连接 API 34 x86_64 模拟器；没有可用 ARM64 真机。未测设备与系统行为不以构建
成功代替。后续各阶段结果记录在此文件。

## AU-02

- `KeyboardIdleTest` 2 项主机测试通过：1.8 秒稳定间隔，连续直输、触摸长按、
  预编辑、候选交互、空临时会话均阻止提示。
- API 34 `UpdateToolbarTest` 通过：静态提示点、触摸时隐藏但设置按钮仍能点击、
  英文/数字/密码呈现、候选优先、更新清除。真实 `ExternalHostTest` 2 项通过，
  覆盖 g/g/l/l → 王、选词、大小写、长按退格及隐藏后取消重复。
- 修正旧测试在上屏后仍寻找“收起”的断言，改为验证候选区域随提交消失。
- 服务在新输入框、显示/隐藏和重建时重置静置间隔，销毁时移除计时器和订阅。
  检查结果只改变缓存/可用版本，不改变输入状态；候选列表存在时不给设置提示占位。

## AU-03

- 下载独立于输入服务，仅设置页的用户操作可启动；展示进度、取消中、取消、失败与重试。
  完成后校验 SHA-256、包名、versionName/versionCode、最低 SDK、设备 ABI 和已安装签名。
  API 28+ 支持系统已验证的前向签名轮换历史；多签名和较旧系统使用相同签名集合。
- 安装前再次复核文件，使用不导出的 FileProvider 临时授予精确 APK URI 的只读访问。
  用户明确确认后才进入系统授权/安装；授权返回不自动安装，仍需再次点击。
- `UpdateDownloadTest` 3 项通过：取消清理与进程中断、失败重试/去重、已下载恢复及篡改、
  校验和/包名/版本/降级/系统/错误签名拒绝。发现并修复协程取消后未发布最终状态的问题。
- API 34 系统安装器验证拒绝授权→重试授权→取消安装→Activity 重建，安装包仍可恢复。
  撤销 REQUEST_INSTALL_PACKAGES 时 Android 会杀死应用，因此测试脚本在 instrumentation
  启动前复位权限；这不是应用崩溃或校验失败。
- `android/test-updates.ps1 -Serial emulator-5554 -InstallUpgrade` 通过：10 项专项测试，
  随后用户确认路径从 debug 签名 versionCode 4 覆盖到 5；安装导致旧测试进程结束，
  独立的升级后测试 1 项通过。版本名称均为 0.5.1，仅 versionCode 在本地测试构建中递增。
- 升级前主动导入完整示例主表与辅助表，记录已有配置、码表包与用户词库共 36 个
  引擎数据文件；升级后逐文件 SHA-256 相同，旧下载文件清理、过期提示清除。
- 此次使用本地生成的同一 debug 签名制品、受控检查/传输测试替身和真实系统安装器；
  不声称已经从生产 GitHub Release 下载升级，也没有使用/更改生产签名密钥或发布版本。

## AU-04

- API 34 / Android 14、Pixel 5 配置的 x86_64 AVD，系统安装器
  `com.google.android.packageinstaller`；竖屏 1080×2340，横屏 2340×1080。
- `UpdateIdleHostTest` 在独立进程预置缓存后，真实 Settings 输入框验证：空闲提示点、
  输入 g 与候选展开时无提示、选择王后的空闲恢复、横竖屏、切换输入法后的服务重建、
  点击设置入口。动态无障碍标签读取前刷新 UiAutomation 缓存，防止读到过期标签。
- `UpdateIsolationTest` 对主模式、英文、数字直输和密码场景，在主线程驱动相同的
  Prepare/Ack/候选查询序列，每种条件 1,602 次操作；基线、慢检查+下载、超时+取消
  三种条件下，每条编辑操作及候选顺序完全一致。100 次重复触发仍只有一次检查。
- `AppUpdateTest` 验证已启动检查的限频时间预先持久化、结果缓存和失败手动重试。
  更新成功安装或成功检查无新版本后不留下过期提示。UI 只展示静态角标，没有更新
  Toast、系统通知、声音或振动；下载控制器只由设置页创建。
- 重现脚本默认不实际安装；`-InstallUpgrade` 才执行系统确认覆盖升级。签名 APK
  专项测试使用显式 `update_fixtures` 参数，避免普通测试运行误用遗留 APK。
  空闲提示设备测试也显式启用，预置缓存与实际验收在两个进程中运行。

### 验证边界

- 没有可用 ARM64 真机；API 26、API 35 设备、16 KB 页设备和 OEM 安装器未实测。
  双 ABI 构建和 ELF/ZIP 对齐检查不能代替这些设备运行结果。
- 弱网、超时、断网重试和下载空间不足由传输替身/故障注入覆盖，没有填满设备磁盘。
  系统安装器的空间不足或其他 OEM 安装失败未强制制造；应用保留待安装文件并允许重试，
  系统负责最终签名/权限/安装条件判定。
- 生产 GitHub 发布未执行，生产签名覆盖安装未实测。下一次正式发布须递增 versionCode，
  旧版首次仍需手动升级；没有跨设备静默安装承诺。

## 整体审核与最终回归

- 更新信息的 APK 地址必须属于刚确认的同一个公开正式 Release；客户端和发布脚本
  同时限制 Android versionCode 有效范围。CI 要求完整发布资产包含 android-update.json。
- 后台检查、下载与输入状态分离，键盘仅订阅检查结果；所有下载/权限/安装入口都在
  UpdateActivity。持久化请求间隔覆盖检查途中重建，取消下载在不可取消的清理段内
  完成状态发布，防止卡在下载中。已下载文件在恢复和安装前重新验证。
- 按下/松开才更新触摸状态，移动事件不重复重建键盘模型；工具展开行在预编辑或候选
  出现时隐藏，不挤占选词空间。触摸隐藏角标不会移除设置按钮，点击仍然有效。
- `AppUpdateTest` 最终 5 项通过，包括成功无新版本清除缓存、安装版本过滤和跨 Release
  地址拒绝；与修正缓存读取的 `KeyboardLayoutTest` 2 项合跑，**7 项通过**。
- 扩展设备回归共 31 项：下载 4、JNI 2、编辑器 4、生命周期 6、资源 3、词库 2、设置模型 1、
  键盘布局 2、Settings 外部宿主 2、模式宿主 1、Chrome 4。30 项首轮通过；布局测试的一项
  读到旧符号标签，改为刷新无障碍缓存后两项布局测试复跑通过。Chrome 覆盖实际密码、
  数字、Unicode 编辑、回车行为与输入期间横竖屏；未以模拟编辑器替代这些宿主证据。
- 超时和 ENOSPC 传输故障测试均能清理临时文件并重试成功；签名/哈希/降级包拒绝测试
  通过。使用显式 fixture 参数，普通 CI 不会误用设备上的历史测试 APK。
- Python 发布脚本测试 **4 项通过**；Rust 工作区 **277 项通过**，cargo fmt 检查通过。
  Kotlin 单元测试 **2 项通过**。Debug/Release 构建及 Lint 通过，Lint **0 错误、8 项既有
  警告**（备份迁移规则与图标）；保留 applicationContext 的单例通过注释限定的误报抑制。
- 本地复现脚本以基础 versionCode 5、候选 6 再次运行检查/下载/授权取消和真实空闲提示
  通过；不再执行第二次覆盖安装。最终仓库声明仍为 0.5.1 / code 4，未擅自发布或改版本；
  code 5/6 只用于临时构建与模拟器验证。
- 最终整体审核未发现阻塞项。未验证的真实设备、生产发布和系统异常边界见上节。
