# MI-24 / MI-25 模型准备与资源生命周期

## 策略

`prediction.loading` 缺省为 `on_demand`，旧配置仍按需加载。`preload_keep`
只有在预测开启且选定模型时生效。Windows 保存设置、TIP 激活会发送后台准备；
Android 在允许输入的 IME 生命周期中准备。两端界面提供相同配置字段。
预热只使用固定的“预热 / 完成”测试文本，随后清除推理状态，不读取宿主文本。
`Loading` 包括权重加载、上下文初始化和短预热；完成后才报告 `Ready`。
原生加载不能强行中断；准备有独立 30 秒预算，退出/配置版本变化使旧工作失效。

Windows 继续使用每用户的独立单实例服务；`Prepare` 不抢占输入会话所有权。
跨应用只共享模型权重，切换所有者清除待发布结果与推理缓存。保持模式不因
10～600 秒的普通空闲卸载；关闭、无模型、暂停或系统低内存通知释放模型。
低内存结束后可重新准备，显式暂停不被低内存恢复覆盖。服务异常后下一次
新请求重新拉起进程；再次激活也重新准备。没有后台无限重启循环。
保存发起异步准备，服务接受请求后不依赖设置窗口存活。

Android 隐藏/失焦/敏感输入暂停并释放；重新显示后按已保存策略重建。
服务销毁关闭工作器；连接改变撤下旧会话请求。低内存、严重热状态、节电及
未充电低电量暂停；前台允许期间每秒重查资源状态，隐藏时停止轮询。
系统 `onLowMemory` / `onTrimMemory` 主动暂停，下一次允许的生命周期或输入事件恢复。
预加载不意味着 Android 后台永久驻留。

## Windows 实测（2026-11-05）

同一台开发机、CPU 两线程、Qwen2.5-0.5B Q4_K_M、等待预算 1000 ms。
固定自编前文“明天去”，不是实际用户输入。原始数据：
[保持模式](validation/mi-preload-windows-keep.jsonl)、
[按需模式](validation/mi-preload-windows-demand.jsonl)。

| 场景 | 结果 |
| --- | --- |
| 保持模式首次准备到 Ready | 1372 ms |
| 准备后首次 / 紧接热请求 | 均超时；1105 / 1103 ms 是探针等待结束时间，不是推理耗时 |
| 空闲 11 秒后 | 952 ms，成功返回“出差 / 探亲” |
| 暂停后恢复到 Ready | 1319 ms |
| 按需首次 / 热请求 / 空闲后 | 均超时；冷请求及空闲后仍处于 Loading |

另一次与构建并发的保持模式探针三轮全部超时，不能只展示成功轮次。
按需模式测量也受并发构建影响，以上不是策略速度优劣的统计对照。
1000 ms 到期后隐藏结果，不扩大预算以通过宿主验收。
[驻留采样](validation/mi-preload-memory-loaded.json) 工作集 483.1 MiB、私有内存
454.3 MiB；[释放后](validation/mi-preload-memory-released.json) 12.1 / 7.1 MiB。
这是进程采样，不能等同精确模型分配量。

`probe-preload STORE ID VERSION on_demand|preload_keep` 可复测；先启动同目录
`model-worker.exe`。探针完成会 Close 自己持有的会话。工作器单元测试覆盖首次
预热、保持空闲、取消不重载、暂停释放/恢复、替换失败恢复及关闭释放。

MI-24 实现与真实服务测量已完成；新增策略的设置关闭、服务崩溃、Windows 会话
重新进入和真实内存压力全链路仍缺独立宿主验收，因此整项保留未完成。

## Android 实测（2026-11-05）

API 34 x86_64 模拟器，模型版 APK（同时构建 arm64-v8a 与 x86_64）。
使用仓库自编小型 ONNX 模型验证生命周期，不把其速度冒充 GGUF 速度。
[原始测量](validation/mi-preload-android.json)：首次输入前准备 79 ms、隐藏后
重显 50 ms、关闭并重建控制器 41 ms；PSS 为整个应用，分别 123924 / 142028 /
116661 KiB。这里的“冷”指工作器无加载模型，不是系统页缓存冷启动。

[设备测试日志](validation/mi-preload-android-test.log) 实际 3 项通过、1 项因未配置
评分用 GGUF 包跳过。通过项含模型目录管理、ONNX 加载/预热/释放，以及 Android
设置应用搜索框中连续选择、隐藏/重显、RUNNING_LOW 回收后重新输入和外部编辑。
另有控制器关闭重建验证，不将其描述为强杀系统 IME 进程的测试。
生成包的独立宿主尝试仍超时，属于 MI-23 的未通过项。

MI-25 按模拟器范围验收；ARM64 真机耗电、温度、长时间驻留仍留给 MI-18 / MI-35。
