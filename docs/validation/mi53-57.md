# Android 可选 ONNX 组件验收记录（MI-53～MI-57）

2026-11-25。标准 APK 自带 llama.cpp，可直接使用本地 GGUF；ONNX 模型需要先在预测设置中安装微软 ONNX Runtime 1.31.1。两个版本均需另外准备模型权重。交付范围为项目 GitHub APK。

## 输入和组件管理

| 环境 | 验证路径 | 结果 |
| --- | --- | --- |
| PGZ110 真机，Android 15，arm64-v8a，4 KB 页 | 使用独立包名，从缺组件状态复用本机官方 AAR，安装后手动选择模型并保存；通过 JNI 分别运行 ONNX 和 GGUF | 两个模型均返回结果。真实宿主编辑框收到“北京天气”，后续输入、焦点和选区断言通过。使用中的组件受到保护，延迟移除在下次启动生效 |
| Android 15 模拟器，x86_64，16 KB 页 | 无 ONNX 时运行 GGUF；从设置通过官方地址下载组件，首次中断留下 6,471,626 字节，重试续传后校验安装 | ONNX 请求成功。关闭模拟器网络后，重新启动、标准包与完整包覆盖切换、真实宿主上屏和延迟移除均通过 |
| 预测设置 | GGUF 切换至 ONNX，保存、关闭再打开、试运行；另测横屏、深色及 1.3 倍字体 | 设置保留，试运行得到“天气”。安装组件本身不会开启预测或更改选中的模型 |
| 共享安装器 | JVM 测试覆盖断网、取消后重建与续传、空间不足、错误 ABI、非法路径、大小及哈希不符、失败保留旧库 | 异常走相应失败或恢复路径。更新失败保留旧库的故障注入在 JVM 执行，尚缺两种 ABI 分别在设备端的故障复现 |

官方 AAR 共 55,138,794 字节，SHA-256 为 `d4d50660300ed2c4f38ffdfd5ab5bfa3a22f995f282dda24f42ea3ea55467b49`。提取的 ARM64 库为 34,208,680 字节，x86_64 库为 40,827,944 字节。真机和后续测试复用已有 AAR 及模型。为了补齐 16 KB 环境，SDK Manager 安装了缺少的 API 35 镜像，并在隔离目录中一并安装了它要求的模拟器版本。

真机第一次运行遇到宿主等待超时，调整测试同步后复测通过。测试结束后已卸载真机的两个独立测试包、移除临时数据，并核对原输入法和旋转设置。真机断网冷启动仍待验证。模拟器已恢复设置并关闭。

## APK 体积和升级

同一产品源码、Gradle 8.9、Rust 1.99.1、NDK 27.2.12479018、Release 构建，原生库使用 DEFLATE。四包均为本地测试签名。安装占用用 x86_64 模拟器全新安装后、首次启动前的代码目录磁盘块数计算，包含 APK 和已提取的库，模型与用户数据另计。下表单位均为字节。

| 构建 | APK 下载 | 安装占用 | 从零到具备 ONNX 运行库的下载量 | 同版本运行库下的后续应用更新量，以本次 APK 为例 |

| 双架构基础包（体积基线） | 17,887,070 | 45,342,720 | 不支持 | 17,887,070 |
| 双架构标准包 | 21,926,839 | 54,546,432 | 77,065,633 | 21,926,839 |
| 双架构完整包 | 49,931,571 | 123,613,184 | 49,931,571 | 49,931,571 |
| ARM64 单架构标准包（评估） | 16,237,333 | 未测 | 71,376,127 | 16,237,333 |

标准包已经安装时，首次启用 ONNX 只需增加一次 AAR 下载。若后续更新更换固定运行库版本，则需另计新 AAR；以上均未计入模型权重。

x86_64 模拟器用两套已有的本地同签名旧包（0.11.0 基础包和旧模型包）分别覆盖升级到标准包、再到完整包。逐次比对配置、码表、用户词库和模型的哈希；已选 ONNX 模型的配置也保留。更新通道设备测试 5 项通过。正式签名 APK 的发布、应用内接收该正式更新，以及 ARM64 真机旧包覆盖升级仍待验收。
