# Android 可选 ONNX 组件验收记录（MI-53～MI-57）

2026-11-25。标准 APK 自带 llama.cpp，可直接使用本地 GGUF；ONNX 模型需要先在预测设置中安装微软 ONNX Runtime 1.31.1。两个版本均需另外准备模型权重。交付范围为项目 GitHub APK。

官方 AAR 共 55,138,794 字节，SHA-256 为 `d4d50660300ed2c4f38ffdfd5ab5bfa3a22f995f282dda24f42ea3ea55467b49`。提取的 ARM64 库为 34,208,680 字节，x86_64 库为 40,827,944 字节。真机和后续测试复用已有 AAR 及模型。为了补齐 16 KB 环境，SDK Manager 安装了缺少的 API 35 镜像，并在隔离目录中一并安装了它要求的模拟器版本。

真机第一次运行遇到宿主等待超时，调整测试同步后复测通过。测试结束后已卸载真机的两个独立测试包、移除临时数据，并核对原输入法和旋转设置。真机断网冷启动仍待验证。模拟器已恢复设置并关闭。

## MI-55 与 MI-57 本地补验（2026-11-25）

| 验收项 | 实际操作与结果 |
| --- | --- |
| x86_64 更新失败后的离线冷启动 | 在 16 KB Android 15 模拟器上，经生产下载器安装缓存里的官方 AAR，另写入同长度、哈希错误的候选 AAR。安装器报告校验失败，删除坏文件，旧库摘要保持一致。关闭 Wi-Fi 和移动数据、核对系统无默认网络、强停确认无进程后重新启动，真实 ONNX 请求通过，外部宿主编辑框也收到“北京天气”。 |
| ARM64 安装、更新失败与恢复文件 | Android 14 的 4 KB x86_64 模拟器以 ARM64 转译执行独立包。真实安装器提取 ARM64 库，拒绝损坏的更新，离线重开后旧库摘要仍为 `46e0c16cd515c62a1dd6c5994448b5413705478354bc20a756a5a82634c3ca03`。从 0.11.0 标签重建的独立基础包覆盖升级，配置、三张码表、用户词库、两套模型共 12 个文件的摘要保持一致。 |
| 转译环境的兼容处理 | 原实现在 ARM64 进程里选中了 x86_64 文件。改为按 JNI 实际编译架构选择后，微软 ARM64 库仍在两套 x86_64 模拟器的转译进程中崩溃。现在应用会在加载前提示使用本机架构。4 KB 和 16 KB 环境均验证了该状态；按 Android 默认架构覆盖安装完整包后，系统选用了 x86_64，配置、词库和模型摘要保持一致，离线真实推理成功。 |
| PGZ110 真机边界 | 安装独立旧包时 ColorOS 要求机主图形验证，本轮已取消安装。原包、联网状态和默认输入法均保留。本轮转译结果不能作为真机的离线冷启、更新失败恢复或旧包覆盖升级证据。 |
| Release 构建演练 | 修正后的标准包为 21,910,920 字节，SHA-256 为 `4b857e82d09057ba5a61d04f5fca9619f4e6c152aa4fdfd4113b18706c8be04d`；完整包为 49,913,532 字节，SHA-256 为 `607cc1d506777517924e4c359dd507fe35fe2dd160057c18d371271407513b07`。两包通过签名、16 KB 对齐、ABI、模型库与许可证检查，按发布脚本生成的两份清单分别指向对应 APK，摘要与文件一致。两包使用同一本地测试证书。 |
| 两条应用内更新通道 | 在 API 34 模拟器上，以实际包名 `org.mywubi` 分别从标准 Release 升标准 Release、完整 Release 升完整 Release。应用内更新器读取本地模拟的更新和 APK，经正常校验后打开 Android 安装器。两次均从验收版本号 20 升至 21，设备端 APK 摘要分别为 `2d5c6dd74fbc20565e9d2368308b2a5be20a61fd72e564cf4c72287e07c27078`、`37013881033e3aa79600aeb62e866104bde6935ca4ce0a3bd96b02f59ef45bc0`。安装后的独立测试核对配置、导入码表和用户词库，并确认更新缓存已清理。线上正式更新尚待发布后验收。 |

两次中间失败已单独记录。16 KB 镜像在执行测试期间出现过 ART 和系统进程崩溃，重启同一模拟器并用 Android 自带的提前编译重跑后，冷启动、真实预测和外部宿主输入全部通过（`accepted-aot.log`）。覆盖升级时，Android 在安装尚未解冻时便报告了新版本号；补验等待解冻、确认新进程可启动后再核对数据。标准包结果见 `accepted-release-retry.log` 和 `accepted-release-standard-post.log`，完整包见 `accepted-release-last.log`。旧模型版在转译环境启动时也曾崩溃，其升级通过记录仅来自原生 x86_64 模拟器。

补验全程复用本地 AAR、GGUF、Android 14/15 镜像和构建缓存。原始证据位于 `target/mi53-57-verification/`。文件恢复及旧包迁移见 `accepted-device-5584.log` 和 `follow-history-device.log`，转译故障及修复分别见 `follow-abi-34.log`、`follow-abi-5582.log` 与 `follow-fallback-5584.log`、`follow-fallback-5582.log`，两套 Release 制品及清单见 `accepted-shipping.log`、`accepted-standard-update.json`、`accepted-full-update.json`。
