2026-11-28 在 Windows Sandbox（构建 26100，桌面缩放 200%）中验证本地提交 `7af859d`。通过真实设置页、系统文件对话框、UI Automation 及候选框 MSAA 控件操作。沙盒缺少记事本，从宿主 Windows 复用经典记事本 10.0.26100.8457 及其语言文件。

沙盒内的记事本和任务栏搜索框均通过 `a` 加空格提交「验收词」。搜索框首轮用了设置测试专用的 `--config` 参数，跳过了应用容器读取权限的准备。改从常规设置入口启动后，核对码表的只读权限，并在同一搜索框复测通过。翻页首轮误用了等号，随后在记事本点击候选框「下一页」验证了翻页和上屏。

### 构建与测试

- 构建使用 `cargo build --offline --locked -p im_engine -p settings`。输入法 DLL 的 SHA-256 为 `429687A68CCB69E5938C6AA46A03BEB661D1C4596A0FE20F4C13F07C515B78CC`，设置程序为 `486A2DCAEA6FC55763F3061CB90E7E974554736A59419AC481DA3505ED172122`。
- 定向库测试使用 `cargo test --offline --locked -p im_engine -p settings -p text_render --lib`，137 项通过、3 项按原定义忽略。
- 全工作区使用 `cargo test --workspace --offline --locked --target x86_64-pc-windows-msvc -j4`。首轮发现旧皮肤测试假定零候选时只占一行。更新断言后仍精确核对皮肤上下留白，并保留空候选行。复测 655 项通过、9 项按原定义忽略。
- 严格 Clippy 检查通过了 settings、text_render 和 core_engine 的全部目标。im_engine 仍有原有 COM 裸指针接口、日志打开选项等告警。图标像素循环按检查结果调整后，已单独复测两种字色和字形透明度。
