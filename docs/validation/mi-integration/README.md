## Windows 实际路径

在本轮专用 Windows Sandbox 中注册测试 DLL，不改宿主机输入法注册。Edge 与经典记事本
均完成上屏、模型预测和继续输入；设置程序未运行。主动结束服务 PID 2940 后，基础编码
仍正常输入，下一轮请求启动 PID 3892 并恢复预测。新输入撤下旧预测；两个应用/编辑框
不继承彼此前文。输入 `b` 后热关闭模型功能，再输入 `j` 保留为 `bj`，服务状态为 `Paused`。

干净 Sandbox 首轮暴露出 ONNX 的 VC++ 运行库依赖缺失；打包已补齐 Visual Studio
14.51.36231 的 x64 可再分发 CRT。补齐后 `model-worker --check-backends` 返回 0。
没有要求用户另装 Python、训练工具或开发环境。

最终定位修复版在新测试目录 `C:\MyWubiModelQA2` 复验。冷启动第一轮超时隐藏预测，正文
正常保留“北”；第二轮 `b` 上屏后预测“京”，点击后预测“天气”。
[最终截图](windows-model-prediction.jpg) 的正文因此为“北北京天气”，没有丢掉首轮文字；
候选框位于正文下方。截图是实际工具返回图像，未修改内容。

## 服务探针性能范围

硬件：Intel Core Ultra 7 165U，12 核 / 14 逻辑处理器；CPU 后端，2 个推理线程，
前文固定“北京”，候选仅“天气/大学”，等待预算 1000ms。测试期间有其他构建负载。
重复相同输入会命中缓存，不能据此推断长前文、候选更多或真实打字的分位延迟。

| 模型 | 有效/尝试 | 首次可用墙钟 | 有效请求 P50 / P95 / P99 |
| --- | --- | --- | --- |
| 自编统计 ONNX | 20/20 | 268ms | 15.207 / 15.795 / 268.653ms |
| Qwen2.5-0.5B Q4_K_M | 20/22 | 2858ms | 16.184 / 20.428 / 650.940ms |

原始结果：[ONNX](windows-onnx-service.jsonl)、[GGUF](windows-gguf-service.jsonl)。
GGUF 的两轮冷启动超时未计入“有效请求”的分位数，已体现在尝试次数和首次可用时间中。
两种模型都不据此列为质量达标或默认 200ms 预算下的推荐模型。
