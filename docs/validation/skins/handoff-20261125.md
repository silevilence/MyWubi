| 入口 | 操作与观察结果 |
| --- | --- |

QQ、微信的模拟参数取自 Android 的文件交接协议。此处假设客户端会交出一个可读的内容 URI，并按打开或分享文件的方式调用系统。没有把两组参数指定为某个客户端的固定实现。两个客户端发布后的实际表现由用户日常使用反馈。[Android 文件匹配](https://developer.android.com/guide/topics/manifest/data-element) · [接收其他应用分享的数据](https://developer.android.com/develop/ui/compose/sharing/receive) · [授予临时读取权限](https://developer.android.com/training/secure-file-sharing/share-file)

## 预览与试打

- 使用项目的四键盘模板，在设备保持竖屏时分别选全键盘、拼音九键、形码九键和形码十四键。每种都切换了横屏和竖屏，核对代表键、横屏缩放后的按键高度和候选栏。纯外观「素简」分别搭配内置全键盘、已保存的十四键与自定义映射，核对布局和配置文件。[模板文件](../../templates/mywubi-keyboards-4.mywubi-skin)
- 从十四键预览进入试打，真实 MyWubi 输入法在原生编辑框中选词上屏「一」，退格后编辑框为空且保有焦点。另验多行换行、数字和电话输入「2」、邮箱输入「a」、网址框布局和密码框的安全输入界面。
- 试打中切到独立编辑器，键位从分组键「GH」恢复为日常键盘的「q」。返回试打和预览后，核对三种模式的键盘选择和完整配置文件。重新打开设置再核对一次。
- 在试打框显示「GH」时，由独立验收宿主终止 MyWubi 的调试进程。切入另一个应用的原生编辑框后，确认进程 ID 已更换，日常键盘显示「q」，试用的「GH」已消失。重开设置后配置文件的 SHA-256 与试打前一致。
- 模拟器改为深色模式、字号调至 1.3 倍，复跑四种键盘的横竖预览、七类输入框和跨应用恢复，整条用例通过。随后恢复常规显示并关闭模拟器和 Windows 沙盒。

## 复核

```powershell
adb -s emulator-5580 shell am instrument -w -r -e class 'org.mywubi.ExternalSkinImportTest,org.mywubi.SkinTrialTest,org.mywubi.KeyboardPackageTest#previewResolvesEveryBundledModeWithoutSavingASelection' org.mywubi.test/androidx.test.runner.AndroidJUnitRunner
adb -s emulator-5580 shell am instrument -w -r org.mywubi.acceptancehost/.SkinTrialRestartCheck
```
