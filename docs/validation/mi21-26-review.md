## 失败根因及修复

1. **服务 Ready 不等于生成能按时到达宿主。** 原生成路径在 1000 ms 内经常未完成。现缓存固定公共提示，预加载完成真实生成预热，并优化保持逐 token 等价的语法 greedy 筛选；用户前文与输出不跨请求/所有者缓存。原模型、提示、门槛与预算不变。会改变输出的 JSON 格式推测已移除，保留[失败等价性测试](mi23-rejected-framing-equivalence.log)。
2. **设置立即退出会中断后台交接。** 由设置同步创建独立无窗口工作器，工作器自己读取已保存配置、竞争单实例并准备模型，重试与原生加载不依赖设置窗口存活。
3. **Windows 路径写法导致同一模型再次加载。** `canonicalize` 引入的 verbatim 前缀与普通宿主路径不一致；现在保留调用方绝对路径写法。新增首宿主回归先复现超时，再验证约 217 ms 返回“市”，同时覆盖 61 秒驻留和关闭/再启用。见[修复前](mi24-host-path-before-fix.log)、[修复后](mi24-host-path-after-fix.log)。
4. **Android 扩展验收读到旧无障碍节点。** 所有候选可见性断言统一使用既有清缓存助手；要求与生产逻辑未放宽。失败轮次和逐项复测均保存在[最终回归索引](mi23-android-regression-summary.json)。

## 质量结论与明确限制

- **当前模型仍不推荐启用。** 新保留集直接生成参考命中 1/32、展示 9/41、停止负例误展示 0/9；三方法全部 123 条链保留零步和失败。唯一三步生成链出现重复回环，宿主演示“天气晴朗多云”也有语义矛盾。完整结果见[独立评测](../model-input-generation-evaluation.md)。精确参考匹配不是语义准确率，推理提速不能证明质量提升。
- **未取得独立人工票。** 已提供两人独立标注、第三人裁决、多种合理续接及无法判断项的[规程](mi26-human-review-protocol.md)和空白盲审材料；代理定性分析单列，不冒充人工。MI-26 要求的判定方法与可复现适用结论已完成，不声称人工质量验证完成。来源版本、许可证、所有排除项和数据哈希均记录；此次保留集不得再用于后续选参。
- **不承诺任意宿主每次都有候选。** Android 系统设置搜索框高负载仍可能超过 1000 ms，按预算静默回退；[原失败记录](mi23-android-settings-budget-limit.log)保留。通过范围是已实测的可用宿主，未扩大期限，也未替换模型来通过验收。
- **生命周期验证有明确边界。** 资源压力使用生产 OS 监视器调用的同一回调与真实模型，未物理耗尽开发机内存；新系统会话使用全新 Sandbox，未注销开发机桌面。原生加载不能强行中断，关闭后旧工作不能发布，原生工作结束才释放；释放稳定态工作集约 11.4 MiB，加载中瞬时高占用也保留。
- **真机范围未冒充完成。** ARM64 耗电、热状态及长时间稳定性仍为 MI-18 / MI-35 的待验内容，MI-25 只按其原定模拟器范围通过。

原先失败日志、拒绝的优化实验、超时与质量失败样本均保留。此次修复范围内没有尚未关闭的验收阻塞；以上限制不等于全部平台性能与模型质量已达标。
