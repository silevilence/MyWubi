# AK-17 抬手到候选显示的真机验收

PGZ110（Android 15、ARM64）在独立编辑器输入 `p`。应用按抬手时的手势决定输入，屏幕出现首选「这」后点选，再从编辑器的 TextWatcher 回读正文并清空。正式构建使用隔离包名、验收签名和允许 shell 采样的清单。输入法独立运行，采样时系统记录的无障碍服务状态为关闭。

每轮 65 次，前 5 次预热，后 60 次取第 57 个值作为 P95。三轮共核对 195 次候选像素和上屏。单位均为毫秒。

| 真机端点 | 第一轮 P95 | 第二轮 P95 | 第三轮 P95 |
| --- | ---: | ---: | ---: |
| 按下到抬手 | 47.0 | 48.0 | 48.0 |
| 抬手到候选实际显示 | 64.5 | 56.5 | 56.0 |
| 按下到候选实际显示 | 110.5 | 103.7 | 102.3 |

三轮抬手到显示的 P95 均超过 50 ms。三轮按下到显示的总时延均通过 SI-17 的 P95 ≤200 ms、P99 ≤300 ms 要求。

## 抬手后各阶段

| 阶段 | 第一轮 P50 / P95 | 第二轮 P50 / P95 | 第三轮 P50 / P95 |
| --- | ---: | ---: | ---: |
| 系统把抬手送到输入法 | 2.6 / 3.2 | 2.5 / 3.0 | 2.4 / 3.1 |
| 输入法处理抬手 | 7.8 / 11.7 | 7.6 / 10.5 | 8.2 / 11.2 |
| 处理结束到开始界面遍历，含等待和重组 | 10.0 / 14.7 | 7.5 / 8.9 | 6.6 / 8.0 |
| 遍历开始到候选栏绘制，含测量与布局 | 9.3 / 18.8 | 8.4 / 10.2 | 7.8 / 9.2 |
| 候选栏绘制到提交渲染队列 | 1.6 / 2.0 | 1.6 / 2.2 | 1.7 / 2.1 |
| 提交到 GPU 完成 | 8.7 / 10.8 | 8.9 / 11.2 | 9.1 / 11.2 |
| GPU 完成到屏幕呈现 | 13.1 / 17.5 | 12.3 / 17.8 | 10.6 / 17.6 |

输入法处理完抬手到开始绘制候选，三轮 P95 分别是 30.7、24.3、16.9 ms。GPU 完成后，等待屏幕真正显示的一段，三轮 P95 都接近 18 ms。各阶段的 P95 可能出现在不同次输入。整段 P95 按每次抬手和其对应屏幕帧直接计算。

## 改动与对照

同一部手机和编辑器、同一份 ARM64 核心、相同轨迹及采样方式，分别安装基线 `1a8e5a9` 和本轮代码。取两者各自最初的 5 次预热加 20 个正式样本。抬手到显示 P95 从 81.7 降至 72.3 ms。这组短测用于比较改动，门槛按上面的三轮结果判定。

另用原生 Android 滚动视图和文本控件做了 5 次预热、20 次正式输入的对照。抬手到显示的中位数为 63.7 ms，P95 为 64.5 ms。同规模的优化版 Compose 中位数为 55.8 ms，P95 为 72.3 ms。原生控件的尾部耗时有所下降，中位数变慢，P95 仍超标，最终保留已完成手势和选词回归的 Compose 实现。

普通候选先读取 12 条，接近末尾或展开时取回完整窗口。输入法把候选和键盘主体的重组分开，复用候选槽和按键预览，文字与当前查询的触摸目标分别更新。特殊输入浏览、翻页以及已授权采集保留完整窗口。

正式测量在每轮预热和结束后采样独立输入法进程，共六点。第一次预热后 PSS 为 127.3 MiB，末次为 110.2 MiB。此前 30 分钟、1000 次布局切换增加 5.7 MiB，属于前一轮构建的独立长测。[内存长测](keyboard-switch-pss.jsonl)

## 复核

事件时刻直接取自 Android 投递的 MotionEvent。候选绘制只记录操作标签，不含候选词和正文。系统提交的帧通过 GPU 完成栅栏匹配 SurfaceFlinger 图层呈现时间，并通过 Perfetto 的显示帧再核对一次。屏幕取样在该帧呈现后进行。校准坐标来自同一字号、方向及布局的 PhysicalPresentationTest。

正常应用已构建 Debug、Release 和仪器测试 APK，使用本地 ARM64、x86_64 核心及既有资源。正式验收 APK 只打入 ARM64。完整的三轮数据、两个 APK 和核心的摘要以及六次 PSS 采样见记录。[分段统计](release-latency.json) · [逐次事件、帧号与栅栏](release-frames.json)

Android 单元测试 23 项通过。首轮 12 项真机用例中，11 项通过；隐藏键盘的取消用例在 ColorOS 上只把测试界面送到暂停状态。改为先回到桌面、确认界面停止，再返回同一界面后，两项定向复测通过。最后六项真机回归全部通过，覆盖长按与滑动、快速输入与取消、大字号展开、查询变化时取消旧候选的按压，以及在独立编辑框中通过展开和横滑两种方式提交第 15 个候选。

验收结束后已移除两个隔离测试包。默认输入法、已启用输入法列表、此前安装的验收宿主 APK 摘要及日用 MyWubi 配置摘要均与测试前一致。

在仓库根目录以相同资源运行。先给验收用 Release 变体启用 shell profiling，并从同一布局的仪器测试报告导出坐标（`-e presentation_export true`）。

```powershell
python scripts/validation/measure_candidate_release.py --serial $serial --package $isolatedPackage --geometry $geometryJson --output $rawJson
python scripts/validation/candidate_presentation.py $rawJson $perfettoTrace $traceProcessor --require-ak
```
