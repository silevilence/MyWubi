## 行为与数据

默认关闭，在双端输入设置中启用「上屏后显示字词预测」。只有成功确认上屏后才召回；
「北→京」只补剩余部分，「北京→天气」追加下一词。显示预测时，空格选择第一项，
数字按显示顺序选择，也可点击或触摸；回车仍交给宿主。继续输入编码立即撤下预测，
不自动顶字、改写或整句续写。模型结果尚未显示时，空格和数字仍按普通输入处理。
失败前拒绝可重试，结果未知清除上下文；候选身份/版本在显示和提交两端校验。
Windows 鼠标按下时冻结命中区域，松开后在 TSF 原线程复核前文并提交。

词典含现有码表/用户词条，以及从固定版本 rime-pinyin-simp 派生的 47,953 个中文词，
生成文件 598,344 字节。`scripts/build_prediction_lexicon.py --check` 校验再现；
来源、Apache-2.0 许可与作者分别见 `tables/sources.json`、
`tables/licenses/rime-pinyin-simp-LICENSE.txt` 和对应 AUTHORS 文件。
`prediction_pairs.tsv` 是 MIT 自编小型搭配表，不是训练完成的模型。
运行时在后台载入阶段构建共享只读索引；关闭时不构建索引。召回最多检查十六个后缀、
每个后缀 1024 行，去重后最多 64 项，产品显示受候选个数限制。
完整词的较短内部后缀不再启动新续接，例如「分钟」不从「钟」接「头」。仍允许完整词
扩展和显式搭配，例如「北京→大学/天气」。这不是语义分词器，连续接受首选仍不能保证
句子通顺；词库收录的歧义扩展也不自动等于当前句子的合理续写。

## 上下文与平台边界

共享层只保留最多 256 个 Unicode 字符，不持久化，不写入日志。
Windows 使用有权限的 TSF 只读编辑会话，先检查 InputScope、只读状态与选区。
经典 Unicode EDIT 的 TSF 桥接可能返回空范围，回退只读取当前行光标前最多 512 个
UTF-16 单元；过长或不可读时使用本会话已确认提交。经典密码控件同时检查 ES_PASSWORD。
宿主提交通知可能早于正文更新，20ms 短定时复核放在消息队列空闲时执行；点击仍即时复核。
它不是推理等待预算。外部通知/点击前无法重读时撤下旧建议，避免猜测正文是否改变。原生 TSF 读取也不包含光标后文字。

Android 使用 InputConnection.getTextBeforeCursor(512)，校验 UTF-16 后截取前文。
密码、直接输入、NO_PERSONALIZED_LEARNING 场景关闭上下文；连接/输入框切换、外部选区
变更、隐藏、重建及模式改变使预测失效。自己造成的选区回调采用有界预期位置记录识别。
配置热开关保留待输入编码，兼容没有 prediction 段的旧配置。
