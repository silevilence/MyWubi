# 临时输入与全拼码表

临时模式只持续一次输入：选词或提交原文后返回主码表。它不切换 Windows 的全局中英文状态。

## 配置主码表

在 `.dict` 文件的 YAML 头中配置：

```yaml
---
charset: abcdefghijklmnopqrstuvwxyz
max_code_len: 4
temporary:
  key: '`'
  pinyin_table: pinyin.dict
  english_table: english.dict
  reverse_lookup: true
---
```

- `key` 缺省或为空时关闭功能。非空时必须是一个非空白可打印字符，不得属于主码表字符集，也不能与当前选词、翻页快捷键冲突。
- `pinyin_table` 指向声明了 `type: pinyin` 的码表；未配置时菜单仍显示拼音及不可用原因，不能进入拼音模式。
- `english_table` 可为空，此时临时英文只输入原文。配置了路径但文件错误时显示错误，不将它当作主动关闭词组功能。
- 两个路径均支持绝对路径，相对路径基于主码表文件所在目录。
- `reverse_lookup` 默认关闭。开启后按完整候选文本反查主码表文件，不包含仅存在于用户词库的编码，不逐字拼凑。多个编码去重后按短码优先、同长度字典序显示。

设置程序的“码表与词库 → 管理当前码表”提供这些配置、类型选择、YAML 预览和校验。跨目录另存会将辅助引用转换为原目标的绝对路径，避免指向新目录中的同名文件；如需整套迁移，可以保留目录结构并使用相对引用。

## 操作

| 阶段 | 操作 | 结果 |
| --- | --- | --- |
| 主模式，编码为空 | 临时入口键 | 显示 `1 拼音 / 2 英文` |
| 主模式，已有编码 | 临时入口键 | 仍按主模式规则处理，不打开菜单 |
| 菜单 | 1 / 2 | 进入可用的对应模式 |
| 菜单 | Backspace / Esc | 取消菜单 |
| 临时输入，有候选 | 空格 / 有效数字编号 | 选词上屏并返回主模式 |
| 临时输入，无候选 | 空格 | 原文上屏并返回主模式 |
| 临时输入 | 回车 | 原文上屏并返回主模式 |
| 临时输入，有内容 | Backspace | 删除一个字符，删空后仍保留临时模式 |
| 临时输入，内容为空 | Backspace | 返回主模式 |
| 临时输入 | Esc | 丢弃本轮输入并返回主模式 |

空缓冲的空格/回车不会上屏空文本，无效数字编号不修改输入。空格不会成为英文内容，也不会在提交结果末尾补空格。数字保持选候选语义；本版本不把数字键作为临时英文的原文字符。

两种临时模式都关闭唯一候选自动上屏和超长顶字。辅助码表中的临时入口、万能键等功能设置不生效，也不会递归加载它们引用的其他码表；数据格式仍需通过校验。

临时英文保留大小写与英文标点。标点不触发形码自动选首选上屏；回车保留完整原文。临时英文的可打印标点和临时拼音的单引号优先于标点选词/翻页快捷键。需翻页时可将全局翻页键配置为 PageUp / PageDown 等非冲突键。Ctrl/Alt/Win 组合键继续透传。

## 全拼码表

```yaml
---
type: pinyin
max_code_len: 64
---
```

字符集固定为小写 a～z，无万能键。可以省略 `charset` 与 `wildcard_key`；显式声明其他字符集或非空万能键会报错。`max_code_len` 统计字母数量，不计单引号；未配置时沿用码表默认值 4，因此词组码表应显式设置合适上限（1～255）。

正文继续使用制表符分隔的 `编码<TAB>文本<TAB>权重`：

```text
ni	你	100
ni'hao	你好	100
ni'hao'ma	你好吗	50
zhong'guo'ren	中国人	100
xi'an	西安	50
xian	先	100
```

多音节词条在文件中必须完整标注每个音节边界。纯汉字词组校验字数与音节数；混合文本由作者标注字音关系，程序不推断读音。语法校验拒绝空音节、首尾单引号、连续单引号以及字符集外字符，不检查音节对应汉字的读音是否正确。多音词可用不同编码分别收录。

输入可省略任意边界：`zhongguoren`、`zhong'guoren`、`zhongguo'ren` 和 `zhong'guo'ren` 都能匹配“中国人”。显式输入的边界必须存在于候选中，因此 `zhon'guoren` 不匹配。输入 `xian` 可见“先”和“西安”，`xi'an` 只匹配“西安”。

尾部允许尚未输完，例如 `ni'h` 能前缀补全“你好”；但 `nh`、`ni'h'ma` 不会跳过中间字母匹配“你好”或“你好吗”。`ni'` 限定后面还有音节，因此不匹配单字“你”。前导或连续输入的单引号被消费但不写入缓冲；其他错误边界保留原输入，显示无候选，允许退格修正。

只接受小写字母形式，不转换大写输入，也不支持声调符号。拼写约定由码表提供；不内置简拼、模糊音、纠错或整句自动组词。原文提交保留用户实际输入的单引号。

## 加载与故障处理

辅助文件在会话外加载并只读共享。启动时单个辅助文件失败不影响主码表，菜单显示不可用原因。运行中监听主码表、辅助文件及配置变化；成功才整体替换快照，失败则保留旧快照并记录日志。新引用即使尚不存在也会监听其目录，文件恢复后可再次尝试加载。

成功重载、失焦或中英文切换会取消临时输入并清理 composition。提交前宿主拒绝编辑时保留临时输入供用户重试；已写入文字但后续清理失败时不重复提交。

## 示例与验收入口

小型配套码表位于 `core_engine/tests/fixtures/temporary/`，仅用于演示与验收，不是完整拼音词库。可复制整个目录后将 `main.dict` 选为主码表。

自动化检查：

```powershell
cargo test --workspace
cargo fmt --all -- --check
cargo clippy -p core_engine --all-targets --locked -- -D warnings
$env:CARGO_NET_OFFLINE = 'true'
cargo bench -p core_engine --bench dictionary_bench -- temporary_100k
```

离线变量用于避免 Criterion 收集 Cargo 元数据时下载无关平台依赖；执行完可在该终端移除此变量。基准使用 10 万个合成三音节词条，包含高重码的宽前缀检索，返回全部匹配结果，与会话分页前的检索规模一致。内存统计为存活分配请求字节，不等于操作系统工作集。

真实 TSF 验收需在已注册本次构建的 MyWubi TIP 的 Windows 环境中进行：验证菜单不写入宿主、部分分隔、两种模式的提交取消、上屏后返回主模式、反查提示、切焦点、热重载和候选窗口位置。设置程序界面验收和模拟编辑 adapter 的行为测试不能替代这项检查。

Android 尚未建立前端；后续 JNI / Compose 接入应复用 `InputMode`、`TemporaryTables`、核心事件及以上行为样例，不自行复制另一套匹配规则。
