# MI-02 通用辅助输入契约 v1

`core_engine::assistance` 仅声明纯 Rust 数据、后端 trait 与校验规则，不依赖平台、
GUI、模型文件格式或推理运行库。实际适配器在 `model_input`，Windows DLL 不链接它。

`ScoreRequest` 携带已提交前文、当前编码、任务、语言和现有 `CandidateId`/文本。
`RequestKey` 复用 CP-04/08 的 `QueryRevision`、`EditToken`，并加入视图、上下文、
模型、配置及请求版本。上层必须在正文变化、编辑器切换、候选/编码变化或配置替换时
更新相应版本；响应投递时与当前 key 完整比较。后台计算开始时校验不能代替投递校验。

后端能力分别声明 Rank/Predict 评分、可选提出字词、语言、上下文/候选/编码限制、
增量状态和合作取消。限制以 Unicode scalar 计数，适配器必须额外检查模型 token 限制。
只支持评分的模型仍可重排外部召回的联想；未实现 propose 默认返回 Capability。
提出结果仍须经过 MI-10 的单字词召回策略和合法性检查，不能直接写入正文。

后端负责分词、输入构造、多 token 候选及长度处理；不返回解释、聊天消息、KV 或 LSTM
状态。返回值为每个输入身份恰好一个有限 f32，值越大排序越靠前；不是已校准概率，
不同模型之间不可比较，阈值/长度归一化由版本化模型适配与独立验证确定。

`ModelSession` 在调用前校验能力/期限，调用后校验期限/取消和候选覆盖；任何失败
清空内部状态。编辑器、会话、runtime、上下文、配置或模型更换也清空状态。
模型可在同一上下文下复用前文状态及隔离候选分支；首版守卫在上下文版本变化时保守
清空，不保证追加文本的增量复用。适配器内部状态永不回流到业务层。

错误码覆盖协议、能力、限制、缺模型、加载失败、格式/架构/算子不支持、推理失败、
无结果、超时、取消、过期、候选缺失/重复/未知和非有限分数。不携带输入文本；
请求/候选故意不实现 Debug。取消标志和单调时钟不序列化，IPC 只能传递受限的
剩余预算并在接收进程重建 deadline。取消不等于计算停止；非合作后端由 MI-08
有界调度与 MI-12 进程生命周期限制资源。

三种产品排序模式不进入模型接口；基础模式不创建后端，另外两种模式只消费经校验的
身份/分数。契约本身不变更现有 `SelectCandidate(QueryRevision, CandidateId)` 选词协议。
产品展示与提交的集成验收属于 MI-09/13/15，不能据契约测试宣称已完成。

验证：`cargo test -p core_engine --test assistance_contract --locked`，覆盖能力/语言/
Unicode 边界、非法身份、无结果、非有限分数、不兼容协议、所有版本维度失效、
上下文/编辑器状态重置、推理错误、取消/超时和仅评分后端的联想调用。
