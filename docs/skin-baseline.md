# SK-01 视觉与验证基线

固定于 2026-11-14。状态样例为 `validation/skins/states.json`；全部是非个人合成数据，预览不得读取最近输入。本文件固定目标与测量口径，不把设计样例当作设备验收。

## 视觉目标

三套方案为墨绿（jade）、素简（plain）、高对比（contrast），各含浅/深两套色板。JSON 色板依次为背景、正文、次要文字、选中底、选中字；正文/次要文字对背景及选中字对选中底至少 4.5:1。序号、提示、模式信息不得混入提交文本。禁用项不可选，仍显示不可用原因。

Windows 推荐正文 14 pt、提示 11 pt，横排优先，溢出转竖排并支持滚动；圆角 8 DIP、选中圆角 4 DIP、边距 8×6 DIP、边框 1 DIP。高对比方案不使用透明背景和阴影。Android 使用 sp/dp，保留现有键位、触摸范围、手势和键盘高度偏好。换肤保留用户字号及布局。

## 旧版与轨迹

Windows 旧外观固定为 14 pt、主色 ARGB FF1E88E5、背景 FFFFFFFF、高亮 FFFFD54F；正文由背景亮度选择 FF202020/FFFAFAFA，保持旧配置解释。Android 旧色板见 `Theme.kt`：浅底 E9EEEB、正文 192C27、主色 245D51；深底 191F1D、正文 E1E8E4、主色 9CD3C1。

对每种状态保存编码、候选身份/顺序、选词、正文、预编辑及 consumed；只换外观时这些结果必须不变。轨迹包括逐键输入、退格、翻页、数字/空格选词、回车原文、失焦取消及输入中切换皮肤。固定样例覆盖普通、反查、长词、预测、ZWJ/肤色表情、组合字符、无候选和不可用。

## 测量边界与门槛

原生后台基线命令：`cargo run -p text_render --example skin_baseline --release --locked --offline`。复用本地字体，每种状态/DPI 预热 20 次再测 200 次；单独报告排版+软件光栅 p50/p95，不能解释为按键到可见延迟。结果保存在 `validation/skins/baseline-native.json`。后续比较须同机同样例同构建模式。

真实可见延迟在集中真实宿主验收采集：同一宿主、同一输入序列，记录输入事件和首次呈现的共同时间基准；至少 200 次，p95 增量目标 ≤2 ms。若工具不能捕捉实际呈现时间则保留未测，不能用后台时间替代。稳定逐键路径不得读包/解码；1,000 次切换前预热，之后 GDI 对象/位图/纹理与私有内存应回到稳定平台，记录采样曲线，不能只比较两张截图。

## 环境与统一验收清单

主机：Windows 11 专业版 10.0.26200、Intel Core Ultra 7 165U。本地有 Pixel 5 API 34 AVD、Android SDK/NDK 27.2.12479018 与 JDK 21.0.8；开始时 adb 无在线设备。复用现有缓存、码表和安装产物，不新建干净下载环境。Android 物理设备、ARM64 和 TalkBack 人工体验未被这份基线覆盖。

最终集中验证 Windows 记事本/浏览器、多宿主、100/125/150/200% DPI、四边避让、字体回退、滚动点击、失焦及不抢焦点；验证 Android 320/393/720 dp、横竖屏、1/1.3/2 字体缩放、字母/符号/功能键、按下/禁用/气泡、手势取消、密码、候选展开、旋转和进程重建。先完成构建、测试包和命令行检查，再一次集中操作。证据按自动化、原生预览、真实宿主、物理设备分别记录。
