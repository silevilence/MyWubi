# Emoji 与颜文字

Emoji、颜文字的普通候选追加、独立词库管理和专用查询模式已接通。内置 Unicode 18.0 / CLDR 49 的 3972 条 Emoji，以及许可可追溯的 34354 条颜文字；无需联网补齐。Windows 沙盒真实宿主和 Android API 26/34 模拟器已有交互与字体证据；Android 真机、TalkBack 和 Windows 实际多 DPI 显示仍待验收，尚未完成全部 EM 交付。

## 选择与导入词库

Windows 常规设置与 Android 设置中的表情词库区域，分别提供两类词库的用途开关、词库选择、版本、条目数及完整来源声明。选择“导入词库”会先验证类型、格式与许可字段，再复制到配置目录下独立的 `expressions/imports/` 子目录；原文件可移走，Android 不需要长期保留文件选择器授权。导入不直接激活，仍需保存设置。“使用内置词库”恢复默认选择，保留已导入文件。

Windows 使用现有便携/AppData 配置路径，Android 使用应用私有目录；新建配置及已有配置缺少内置资源时会从随包资源准备。升级不覆盖已有资源和选择。内置文件已被修改或损坏时不会自动覆盖，设置中会显示校验错误。词库列表的“校验通过”表示文件可解析，不代表所有已打开宿主已采用；保存和热重载失败时保留旧的有效配置与资源。

## 全局配置

```toml
[expressions.emoji]
append = false
search = false
# resource = "expressions/custom-emoji.mwe"

[expressions.kaomoji]
append = false
search = false
# resource = "expressions/custom-kaomoji.mwe"
```

`append` 控制普通输入候选后的追加，`search` 控制专用模式可用性。两者均缺省关闭，任一个开启才加载该类资源。省略 `resource` 分别指向 `expressions/emoji.mwe`、`expressions/kaomoji.mwe`。路径相对于共享 `config.toml` 所在目录，也允许绝对路径。主码表切换不修改这些配置；不向主码表 YAML 头写入任何表情设置。

## 独立词库契约（版本 1）

UTF-8 文件第一行为 `# MyWubi Expressions 1`，之后是一个 JSON 对象。建议扩展名 `.mwe`；识别依据是内容，改名为 `.dict` 也不能作为主码表或临时拼音/英文表。普通码表不能作为附加词库。

文档包含 `kind`（`emoji` 或 `kaomoji`）、`name`、`version`、`sources`、`entries`。每个来源必须提供 `id`、`url`、固定 `revision`、`license` 和版权许可 `notice`。每条词条包含：

- `text`：实际输出，逐码点保留空格、反斜杠、ZWJ、变体选择符及组合字符。
- `name`：显示名称；`triggers`：完整触发词数组，用于严格匹配实际文字候选。
- `tags`、`aliases`：查询标签、名称别名及兼容序列，缺省为空。
- `order`：稳定顺序，同分保持原文件顺序；`sources`：非空来源标识数组。

同一输出不能重复收录；多个触发词归并到同一条目，不合并不同肤色/性别等输出序列。文件最多 64 MiB、100000 条。单条输出及每个触发词/标签/别名最多 512 个 Unicode 标量值，拒绝空白输出、控制字符、多行和 Unicode 行/段分隔符；不通过截断或替换字符修复数据。导入生成器必须记录排除原因。资源格式严格校验未知字段和来源引用。

只读索引在快照构建时建立，逐键查询不读文件。完整触发词精确查找，例如“开心”命中，“不开心”不会按子串命中。更宽松的查找只用于专用模式。

## 普通候选追加与分页

主模式及临时拼音按实际文字候选的完整文本查询 `triggers`。匹配顺序是原文字候选顺序、该触发词的 Emoji、该触发词的颜文字，各词库内部保持 `order` 顺序；整个查询按完整输出去重，已有文字候选优先。输出表情不再参与递归匹配。英文、密码/私密范围和上屏后预测候选不追加表情。

原文字页的文字先出现，表情填入该页剩余位置；装不下的表情接着显示在连续的表情页中，之后开始下一组文字候选。不会为了填满一个表情续页而把下一文字页的首选放到页中间。启用追加且有命中时，每个实际页面最多为配置页大小与 9 的较小值，以保证数字 1～9 可选；配置为 10 时，原文字组的第十项也会进入续页。关闭追加或没有命中时保留原分页行为。

例如页大小 3，第一文字页有 3 个词、关联 4 个表情，后面还有 1 个文字候选时，实际页面依次为：3 个文字 → 3 个表情 → 1 个表情 → 最后 1 个文字。表情没有永久展示截断，所有续页均可浏览。手机展开查询使用相同完整顺序，一次窗口最多返回 256 项，可继续查询后续窗口。

桌面页和手机窗口复用同一份只读候选序列及 ID，翻页不重新展开词库。混合候选翻页、修改编码、退出模式、切换资源或宿主范围变化会使旧查询版本失效。表情名称单独作为提示传递，选中时只提交原始输出字符串。唯一文字候选在满码时若有可追加表情，会保留候选供选择；没有表情时保持原自动上屏规则。确定未写入时，触屏会话及 Windows 临时会话允许重试；Windows 主模式保持原清理恢复协议。

## 专用模式的操作

在软件设置中开启对应词库的“专用模式可用”并保存；可以同时关闭“普通输入时追加”。Windows 先使语言栏按钮处于“中”（输入法接管已开启），再右键打开辅助输入菜单，选择 Emoji 或颜文字；主码表声明的辅助入口键也可使用。语言栏“英”表示关闭接管，此时不会打开辅助菜单；它与菜单里的“临时英文”是不同状态。从临时英文进入表情模式，提交或取消后仍返回临时英文。Android 点击键盘工具图标，再选择“Emoji 输入”或“颜文字输入”。词库关闭或不可用时，入口会显示原因。无需在主码表中配置表情编码。

1. 用当前主码表输入并选词。例如先选“禁止”，再输入“自行车”；文字只累积在输入法的关键词栏。
2. Windows 按 Tab 或点击“查找表情”，Android 点击“查找表情”。仍有编码时会先确认当前文字候选；没有候选时保留编码并提示。
3. 浏览表情结果，选择 🚳 才会写入正文。也可以只组合“禁止车”，由本地模糊查找找到“禁止自行车”。

结果阶段点击“修改关键词”返回编辑；Windows 也可按退格或 Esc。再次查找不会重复提交，结果阶段 Tab 不会上屏。点击“取消”退出模式。长候选可滚动查看；Windows 内容超出屏幕时提供上下滚动按钮，Android 可展开全部候选并翻组。名称、匹配提示及回退码点都不会被提交。

## 查询会话与编辑规则

共享协议增加 `BeginTemporary(Emoji/Kaomoji)`、`FindExpressions`、`EditExpressionQuery`，状态中的 `view.expression` 独立提供阶段、累计文字、选词边界和提示。查询编码仍用当前主码表，普通候选追加及上屏后预测不参与。

空格、数字、点击及满码自动选词累积内部查询；执行查找时有编码则先确认当前文字，无候选时保留编码并提示。查询为空不查找、不写入宿主。所有组合与查找操作均为宿主 `NoOp`，包括原始编码上屏、Enter 及取消路径；字面文本插入请求在查询模式中拒绝。只在结果阶段明确选中表情时提交完整输出。

结果阶段退格或 Esc 返回修改，保留查询；编辑阶段退格先删编码，再按完整扩展字素簇删除查询末尾，跨选词边界的组合附加符也一起删除。编辑阶段 Esc 先清编码，无编码则取消整个查询。非空普通缓冲不能进入专用模式，非空查询不能切换模式；空查询可切换两种表情库。成功或取消返回进入前的模式。失焦、输入法关闭、资源重载或隐私范围变化取消查询且不向宿主提交它。

结果分页和窗口可浏览全部结果；重复查找不重复提交。确认前不发布预览，确定未写入时保留结果供重试，部分写入或结果不明时丢弃旧查询与 ID，不重放提交，也不结束从未拥有的宿主预编辑。Windows Tab 在表情模式中优先于自定义翻页映射，其他模式保持原有行为。

## 本地模糊检索

查找可以只输入“禁止”，也可输入“禁止车”“不准骑车”“禁止骑行”找到 🚳；完整名称“禁止自行车”优先排在首位。“猫＋开心”优先满足动物与情绪两个条件，颜文字“高兴/开心/快乐”关联同一批结果。一次选完整词或分次选词的结果一致，无需手动加空格。

结果排序依次是名称/别名完全匹配、名称包含或全部关键词匹配、名称字符有序但不连续的宽松匹配，同级保持词库顺序。没有完整匹配时，标题和每个结果都会标明“部分匹配”；不存在相关项时为空结果，不把查询文字上屏。普通自行车不满足“禁止车”的限制条件。“不开心”按负面情绪处理，关系表未覆盖的表达可能需要改词，首版不理解任意自然语言。

名称和匹配提示均不进入正文；不同肤色、性别与组合保留，所有结果可翻页/展开。索引在加载时建立并共享，查找完全本地，不使用模型或联网。具体关系、许可、分词与否定处理范围见 `expressions/SEARCH-RELATIONS.md`。

## 字体与显示

Windows 候选框和设置中的表情预览使用系统 DirectWrite / Direct2D 排版与彩色字形，继续由轻量分层窗口显示。Android 使用系统字体与 Compose。软件不下载字体，也不替换词库中的原始字符；系统不支持的单个字符或组合会显示名称与 `U+...` 码点，选择后仍提交完整原文。设置中的“表情显示预览”可检查单个 Emoji 或一条颜文字。

完整数据集不等于系统字体支持全集。例如本次 Windows 字体对部分家庭、旗帜和新版本 Emoji 使用回退；旧 Android 系统需要回退的条目更多。宿主应用可以采用不同字体，因此正文显示可能与候选框不同。Windows 预览输入框仍由 egui 绘制，请以下方系统字体预览为准。

当前已验证 API 26/34 模拟器上的横竖屏布局、1 倍/2 倍 Compose 字号、真实系统 2 倍字号下的外部宿主输入，以及 Windows 明暗主题、14/28/56 字号和长候选滚动。实际多 DPI、Android 真机与 TalkBack 尚未验证。Edge 157.0.4341.42 的一次表情提交在本次环境产生两次同值 composition 更新，最终正文只含一份表情，但需两次撤销才清空或恢复被替换的原文；普通中文逗号也复现相同行为。这项撤销兼容限制尚未修复，不能据此推断表情重复上屏。

## 失败行为

启动时某类附加资源缺失、损坏或类型不符，只隔离该类资源，保留具体路径与错误，其余词库和主输入继续工作。两个用途均关闭时不访问对应文件。

热重载失败不发布新快照，保留旧的有效配置与词库；失败依赖路径仍交给现有监视机制，修复后可重试。资源错误由共享核心产生，两端使用相同校验逻辑。配置保存拒绝把已存在的表情资源指定为主码表；手改配置绕过保存时，运行时加载再次拒绝。

保存前也校验已启用的附加资源；失败不覆盖现有配置。关闭两种用途后，允许保存尚未安装或暂时不可用的资源路径。

验收记录见 `docs/validation/expressions.md`。显示和真实宿主验证未完成前，不宣称全部字形已支持。
