# MI-20 条件评估：暂缓微调或蒸馏

2026-11-04。MI-05 已记录两份现成 GGUF 的零首选净收益、错误改序和截止有效率不足，
因此启动本项条件评估。结论是暂缓训练，先补足独立数据、候选召回与设备测量。
这完成的是“是否值得开始训练”的评估，不是训练交付，也不解除 MI-05/17/18 的门槛。

## 先排查不需要训练的因素

同一前文与合法候选下已比较 Qwen2.5-0.5B Q4_K_M、Qwen3-0.6B Q4_0、轻量字符统计图，
并分别测前文重算与缓存命中。更小的 SmolLM2-135M 因主要面向英语未冒充中文方案。
Qwen3 热调用更快，但排序 test 仍为 5/12，与基础相同，原正确改错仍为 2/5。
具体分位数、文件来源和许可见 [首轮比较](model-input-comparison.md)。

排序召回缺 1/12、联想召回缺 2/8，先修正召回。当前样本无真实宿主采集，不能证明
设备上获取的前文正确；前文错误必须由 MI-06/07 修复，不能依靠训练掩盖。
固定首位可以保护已有首选，但不产生首选净收益；候选分支逐一解码的成本也不会
因为读取一个决策分数就自动消失。

## 可复现的小实验

`model_input/tools/assess_adaptation.py` 在已有原始分数上进行 26 个配置的开发集对照：
保留基础排序；以及 5 个基础位置惩罚系数 × 5 个分数间隔阈值。
调整分数为 model_score − penalty × log(1 + base_index)，未达到间隔则保留基础。
只在 dev 的 6 个排序病例选择参数，优先首选数、其次少改错；并列保留先出现的基础
对照。test 标签不参与选择，已通过变更所有 test 标签而保持所选参数不变的检查。

| 对象 | dev 所选位置惩罚 / 间隔 | dev 首选（基础 1/6） | test 首选（基础 5/12） | test 改错 / 改对 |
| --- | --- | --- | --- | --- |
| Qwen2.5 | 0.1 / 0 | 3/6 | 5/12 | 2 / 2 |
| Qwen3 | 0 / 0 | 2/6 | 5/12 | 2 / 2 |
| ONNX 统计 | 0 / 0 | 3/6 | 4/12 | 2 / 1 |

开发集改善没有在 test 回归片段产生净收益。由于这组 test 在 MI-05 已被查看，
这里明确只是回归复查，不能作为新的独立保留测试或概率校准证明。
阈值没有写入产品配置，脚本没有训练语言模型或把分数转换为虚假的正确概率。

```powershell
python model_input/tools/assess_adaptation.py model_input/evaluation/results/qwen25-cpu.json
python model_input/tools/assess_adaptation.py model_input/evaluation/results/qwen3-cpu.json
```

全部试验配置与输出保存在 `evaluation/results/qwen25-adaptation.json` 和
`qwen3-adaptation.json`（均相对 `model_input`）。实验仅使用仓库自编样本，不采集、
上传或保存用户实际输入，不从模型包执行脚本。

## 数据、资源与下一步判断

现有 train 只有 8 例，足以验证评测链路，远不足以覆盖候选位置偏差、概率校准、
生僻词和跨领域泛化。后续数据应保留真实前文、编码、当前合法候选及目标身份，
按来源文档隔离 train/dev/test，单列召回失败、正确首选保护与长尾词；不得加入未来
后文作为输入。候选排列需打乱并保存原始身份，避免学到“永远选第一项”。
当前 5 个原正确 test 病例不足以可靠估计 1% 误改目标，需要新的独立评测数据。

监督微调可以评估任务适配，专用小决策头或蒸馏可以评估成本下降；二者都必须对比
不训练的基础排序和现成模型，不能凭架构名称预判收益。蒸馏还需要质量已证明的教师，
当前两份小模型的误改结果不支持直接拿它们作金标准。决策头也不保证跳过主体推理。

本机只核实了 CPU 推理资源，未核实 GPU 训练容量、合法外部训练语料或训练预算。
因此本轮不安排微调/蒸馏训练，不从零预训练，也不在用户设备默认训练。
只有独立数据表明任务适配有稳定收益、轻量基线仍不足、且资源与许可明确后，
才值得另拆数据、训练、量化与双端验证任务。任何新模型仍需经过同一接口与模型包，
重新通过未查看的保留集及真实设备验收；本项结论不意味着新模型已经存在。
