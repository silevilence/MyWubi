## 已实施部分的验证

- `cargo test --workspace`：300 项通过，0 失败。已有 TSF 导出符号 LNK4104 提示仍存在，
  本次未改动该导出配置。
- `cargo test -p model_input --all-features`：15 项通过；真实大模型测试按约定默认忽略，
  已另用两份固定哈希 GGUF 显式运行分支隔离、重复评分与重置验证。
- `cargo clippy -p model_input -p core_engine --all-features --all-targets -- -D warnings`
  与 `cargo fmt --all --check` 通过。
- ONNX 统计/LSTM 导出、词表和独立 NumPy 数值参考逐字节再现，误差要求 1e-6；
  Git 中的 ONNX 字节与工作区相同，不发生 Windows 换行转换。
- 同一进程成功完成 ONNX → GGUF → ONNX 的加载、评分和 generation 切换；
  坏图切换不破坏当前模型，活动模型不能删除。
- Windows CPU Release 比较保存每次分数、延迟、失败与截止回退；没有主线程端到端、
  RSS/PSS 或 30 分钟设备稳定性结论。
- NDK 27.2.12479018 / API 26 的 Android ARM64 库交叉构建通过；没有宣称 ARM64
  真机或最终 APK 可用，Android x64 本轮也未重新执行构建。
- MI-20 实验逐项复现，修改 test 标签不改变开发集所选参数；已查看的 test 片段只
  当作回归检查，不作为新的独立质量证据。

复核中已修复空闲工作线程保留旧缓存、Windows 导入文件句柄未关闭、规范路径比较、
模型声明能力与实际能力不一致、Windows DLL 误作 Android SO、ONNX 换行转换及未列出
目录的遍历边界。完整产品尚未形成，因此本记录不是 MI-01～20 的整体交付审核。
