# 制作与校验皮肤

从 `examples/skins` 的参数包或「竹纸」单端/双端包开始。完整能力、限额与颜色单位以 [格式契约](skin-package-format.md) 为准。
包版本在本地不可变；同 ID/版本的不同内容会拒绝导入，修改后请增加版本，或另起 ID。原文件被外部修改时，编辑器会拒绝覆盖式导出。

## 在 Windows 制作 Android 皮肤

1. 在「外观 → 皮肤管理与制作」导入模板，或创建内置方案的自定义副本。选择 Android 编辑目标；这不会把 Android 外观应用到 Windows。
2. 修改包信息，给作品分配自己的 ID、版本、名称和作者。包内可只保留 Android，也可保留两端。
3. 选择浅色或深色，修改候选、正文/提示、普通键、功能键、按下/禁用态和气泡参数。缺少变体时先创建变体。
4. 在「图片资源管理」填写资源 ID，再导入共享或当前平台 PNG。同 ID 是替换操作；共享替换影响两端的全部引用。需要独立修改时，先在共享资源列表点击复制为本平台资源，再将角色绑定改成 `platform:id`。
5. 在「静态 PNG 与九宫格」把资源绑定到语义角色，选择拉伸/平铺/九宫格，编辑切片、内容留白和透明度。切片按源像素，留白按 DIP/dp，顺序都是左、上、右、下。选择「参数背景」解除该角色绑定。
6. 检查 Windows 原生候选预览和 Android 示意预览。Android 可切屏宽、横竖屏、字体缩放、按下/禁用、气泡与数字符号样例。当前支持语义背景，不支持把固定 26 键底图当作布局。
7. 导出到新文件。编辑器校验两端明暗资源及 PNG 解码；缺失引用、损坏图片和越界切片不能导出。仍被引用资源不能删除，先明确重新绑定。编辑器不自动清理未知组件或另一端资源。

## 在 Android 检查同一文件

1. 设置 → 键盘 → 从文件导入皮肤包，使用系统文件选择器选取同一导出文件。已导入与草稿选择、已应用是不同状态。
2. 选用可用的外观组件，点击预览当前草稿。这里使用 Android 原生键盘组件和固定测试数据。
3. 保存设置后在外部编辑器输入。检查浅深色、横竖屏、系统字体 1×/2×、候选点击、按键气泡、长按/滑动、数字符号、密码输入和 TalkBack。换肤中有未上屏编码时，核对编码、候选顺序/身份及选词结果。
4. 使用「导出并分享完整包」。导出保留 Windows metadata、未知合法扩展和共享资源，不包含本机配置或个人输入数据。

Windows 的 Android 预览是示意，不是 Android 像素证据。Windows 字体回退、Android 系统字体、屏幕密度和可访问性设置可能不同。
未连接真机时可先使用现有模拟器，但真机、TalkBack 和硬件性能结论必须留待对应设备。

## 性能与故障

图片在加载阶段解码。Windows 共享不可变像素缓存，Android 双变体/角色共享位图；逐键不读包、不解码。
新的完整外观准备失败时保留旧快照。应用前会验证相关平台；另一端资源保留但运行时不解码。
导入损坏图片包可用于检查错误提示，不代表该包可应用。资源预算、PNG CRC、尺寸和九宫格约束可在离线测试中验证。

真实可见延迟、GDI/位图常驻量、多宿主及千次切换资源曲线需按 [基线](skin-baseline.md) 采集，不能以解析或光栅单元测试代替。
本轮已测结果与未测限制集中在 [验收记录](skin-validation.md)。自定义 14/9 键与八向映射属于 AK 系列，联合矩阵不得从普通 26 键结果推导通过。
