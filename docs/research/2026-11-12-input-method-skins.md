# 输入法皮肤机制与设计参考

> 研究日期：2026-11-12。
>
> 目的：为 MyWubi 的皮肤规划提供官方资料依据，重点研究 Windows 候选窗口；Android 仅借鉴颜色语义与可读性要求。
>
> 方法：阅读官方文档、官方仓库和官方皮肤平台。本次未安装、下载或运行竞品，未验证当前客户端完整行为。搜狗、QQ 的部分官方教程年代较早，下面将其作为公开设计机制的证据，不视为最新版客户端的完整功能清单。

## 1. 结论

建议将 MyWubi 皮肤定义为「可分享的候选窗口外观方案」：以参数化颜色、排版和尺寸为基础，配上清楚的本地选择、预览和恢复操作；图片装饰作为后续扩展。这个方向综合了小狼毫的可配置性与搜狗、QQ 的皮肤选择体验，是本研究的设计判断，并非竞品官方结论。

皮肤不能改变候选顺序、候选数量、选词键或输入模式。外观切换应保留用户的阅读字号和布局偏好，并明确提供「恢复皮肤推荐值」。对于形码输入，编码、候选、序号、补码或来源提示应有独立视觉角色，避免只靠一两个颜色兼顾所有信息。

## 2. RIME / 小狼毫：参数化样式

这里讨论的是 RIME 的 Windows 前端 Weasel（小狼毫），不能把它的选项直接当作所有 RIME 前端的统一接口。

- 官方定制文档支持独立设置字体、序号字体、注释字体，以及字号、横向候选、纵向候选和文本竖排；布局具有间距、内边距、圆角和阴影等选项。
- `color_scheme` 与 `color_scheme_dark` 分别指定默认配色和系统深色模式配色，文档注明后者用于 Windows 10 1809+。全局样式可被特定输入方案覆盖。
- 配置保存后需要重新部署生效。[来源：Weasel 定制化](https://github.com/rime/weasel/wiki/Weasel-%E5%AE%9A%E5%88%B6%E5%8C%96)

配色方案具备名称、作者和颜色格式，区分背景、文字、序号、注释、选中候选等语义。官方「输入法设定」可以选择预置配色；自定义预览图需将截图按指定名称放入用户目录的 `preview` 文件夹。[来源：定制小狼毫配色](https://github.com/rime/weasel/wiki/%E5%AE%9A%E5%88%B6%E5%B0%8F%E7%8B%BC%E6%AF%AB%E9%85%8D%E8%89%B2)

**适合借鉴：**语义颜色、明暗配对、字体回退与稳定的几何参数。MyWubi 应将这些能力放入可视化编辑器，并自动生成预览，减少用户手写配置和制作截图的负担。

**证据边界：**本次资料没有证明通用图片皮肤包或动态皮肤协议，不应由「高度可配置」推导出这些能力，也不应把 RIME 配置直接等同于可导入的 MyWubi 皮肤。

## 3. 搜狗：皮肤包与视觉编辑

官方帮助描述四种模式：横排同窗、横排分窗、竖排同窗、竖排分窗，可在外观设置中选择。[来源：皮肤模式说明](https://pinyin.sogou.com/help.php?list=2&q=6)

官方皮肤使用说明将 `.ssf` 定义为 ZIP 压缩文件，包含 `skin.ini` 和图片资源，并描述双击安装行为。[来源：皮肤使用说明](https://pinyin.sogou.com/skins/skin_use.php)

皮肤编辑器将图片组装、字体大小、字体、文字颜色及各模式参数结合起来。教程特别强调拼音区和候选区的位置参数，以及背景拉伸方式；提供编辑器和设计资料入口。[来源：皮肤编辑器说明](https://pinyin.sogou.com/help.php?list=5&q=3)

**适合借鉴：**皮肤作为完整作品，有名字、缩略图和单文件分享入口；编辑时同时检查短候选、长候选和不同布局，而不是仅验证一张固定截图。

**应控制范围：**MyWubi 的首版不需要同时复刻四种分窗模式；优先让现有候选框的横排、竖排和长文本处理一致。`.ssf` 有公开容器描述，并不代表能低成本兼容完整渲染语义。

**证据边界：**本次未找到足以确认 Windows 搜狗当前版本自动明暗换肤规则的直接材料，不据此写入兼容需求。

## 4. QQ：作品展示与图像布局

QQ 官方帮助描述 `.qpys` 为编辑器生成的加密压缩格式，支持双击安装，并规定缩略图、预览图和透明效果图的展示形式；平台接受作者上传作品供用户下载。[来源：QQ 皮肤使用说明](https://skin.qq.pinyin.cn/help/pifu01.html)

官方设计指南将背景、底纹、装饰形象、候选分隔线和文字颜色分开处理。背景支持指定拉伸区域以及拉伸、平铺两种方式；装饰需要锚定规则。按钮区分正常、悬停、点击、不可用四态。[来源：QQ 皮肤设计指南](https://skin.qq.pinyin.cn/help/pifu02.html)

官网皮肤平台有分类、推荐、排行与编辑器入口，并列出相框、动态皮肤分类。[来源：QQ 皮肤平台](https://skin.qq.pinyin.cn/)

**适合借鉴：**皮肤卡片应显示作者、名称、实际候选效果；装饰与内容分层，候选增长时背景可扩展，装饰保持稳定。翻页控件如果可以交互，应有完整状态。

**应控制范围：**「平台存在动态分类」不能证明动画格式、时序或资源限制。首版不承诺 `.qpys` 导入或动态兼容；也无需先建设在线市场。个人作品分享可以先用本地导入、导出完成。

**证据边界：**官方帮助包含较老的版本说明；下载、安装及平台上传链路本次均未实测。没有充分资料确认当前客户端的自动明暗换肤能力。

## 5. Fcitx 5：内容尺寸与图片切片

Fcitx 5 的 Classic UI 主题说明把窗口尺寸拆成文字尺寸、文字边距和内容边距。背景图按九个区域处理：四角保持大小，四边单向缩放，中心双向缩放；候选高亮背景也使用相同规则。[来源：Fcitx 5 Theme](https://fcitx-im.org/wiki/Fcitx_5_Theme)

主题以独立目录及 `theme.conf` 为基础，官方提供用户级目录及配置工具编辑入口。[来源：Create a new Fcitx Theme](https://fcitx-im.org/wiki/Create_a_new_Fcitx_Theme)

**适合借鉴：**先按真实文字和布局计算内容矩形，再生成背景；后续加入图片皮肤时沿用九宫格规则。不要先固定一张漂亮背景，再把不断变化的候选强塞进去。

## 6. 手机皮肤的补充约束

搜狗手机皮肤规范强调文字和背景可分辨、首选和非首选有清晰区分、按键有按下反馈、候选区域减少装饰，并要求不同界面的文字都保持清晰。它也明确区分 Android 与 iOS 的结构要求。[来源：搜狗手机皮肤设计规范](https://shouji.sogou.com/sapp/skindesign/jchtml/designgf.html)

**对 MyWubi 的启示：**跨平台可以共享颜色角色、主题名称和作者信息；Windows 浮动候选窗与 Android 键盘的布局、触控反馈和装饰规则应由各自前端实现。该旧教程中的具体像素尺寸不应直接成为 MyWubi 的标准。

## 8. 对项目架构的建议

以下为基于项目约束的设计建议，不是已实现能力：

1. **共用语义、平台渲染。** 纯 Rust 侧仅承载平台无关的主题数据、校验与兼容处理；系统绘制、明暗检测和图片资源生命周期留在各自前端。Windows 应复用现有 `windows/text_render` 的系统文字渲染及 `UpdateLayeredWindow` 候选窗口，Android 复用 Compose 和现有系统明暗主题能力，无需另引入 GUI 运行时。
2. **皮肤与用户偏好分层。** 皮肤提供推荐配色和几何参数，字号、横竖布局等个人偏好有清楚的覆盖关系。切换皮肤不应意外改变选词行为。
3. **预览采用真实渲染规则。** egui 页面负责选择和编辑，但应复用生产候选的布局、色彩解析和样例数据；必要时由相同 Windows 渲染路径生成静态预览，避免两套实现逐渐偏离。
4. **热切换保持输入稳定。** 解析失败保留上一个可用主题；只在完整主题校验成功后替换快照。切换皮肤不应清空编码、改变候选或重置翻页。
5. **本地分享先闭环。** 自有皮肤包记录版本、稳定 ID、名称、作者与授权信息。导入先校验再安装；损坏、缺资源或版本不支持时给出可操作错误。图片扩展时限制解压路径、数量和解码尺寸。
6. **不把装饰放入按键关键路径。** 主题解析、资源读取和解码在加载时完成；已有候选刷新只使用准备好的数据。图片或阴影不能造成重复解码、无意义重绘或 GDI 资源持续增长。

## 9. 首版验收应回答的问题

- 用户是否能在少量精选主题中看出区别，选择后马上理解实际效果，并恢复原样？
- 编码、序号、候选正文、补码或注释是否在普通与选中状态下都可读？
- 字号增大、长词、颜文字、Emoji、生僻字、横竖切换和不同 DPI 时，是否存在裁切、覆盖或背景异常？
- 明暗切换和应用皮肤时，正在输入的编码、候选内容和翻页位置是否保持？
- 导入损坏主题、缺失字体或缺少图片时，是否仍能正常输入并得到明确反馈？
- 预览与真实候选是否使用同一套布局和颜色规则，差异是否有记录？
- 连续切换主题与候选后，是否出现额外资源占用、闪烁或输入延迟？具体阈值应以当前版本基线测量后确定。

正式实现前应先建立固定样例集和离线渲染基线，再集中完成一次 Windows 交互验收；无需下载竞品皮肤或搭建在线市场来验证首版。
