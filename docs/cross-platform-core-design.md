# 共享核心接口、跨端职责与兼容设计

日期：2026-10-23。状态：实施基准，经第二轮文档审核修订，尚未实现；接口名称为设计名称，落地时可以调整命名，不得改变本文行为契约。审核发现与修订映射见 [审核记录](cross-platform-plan-review.md)。

参考：[现状与工具链](android-readiness.md) · [实施顺序及验收](cross-platform-implementation-plan.md) · [ROADMAP](../ROADMAP.md)。

## 1. 目标、范围与约束

1. Windows 与 Android 使用同一个 Rust 检索、会话和数据规则实现。平台前端表达用户意图、执行宿主编辑并展示结果。
2. Windows 当前可观察行为是迁移基线，包括快捷键优先级、原文提交、临时输入、故障恢复和旧文件兼容；不是只保证编译通过。
3. Android 首版提供形码、持续英文码表补全、一次性拼音、候选选择/展开、数字符号、常规设置、码表管理与现有用户词库能力。入口和布局可不同，规则不能复制到 Kotlin。
4. 不随本轮实现简拼、模糊音、纠错、自动整句组词、词频自动学习、云同步、语音、滑行输入、九宫格、iOS 或皮肤系统。保留 ROADMAP 中独立规划，不能以同名字段声称支持。
5. Android 第一版采用完整字母键盘；内嵌离线码表。发行首先验证 ARM64 真机与 x86_64 模拟器；最低系统版本与精确工具版本在构建验证任务中确定并锁定。
6. 保留 Rust + windows-rs / GDI、egui、Kotlin + Compose 和 rust-android-gradle 既定选型。核心可用 Rust 标准库，不为 Android 顺带进行 no_std 重写。
7. 本次只改文档。AGENTS.md 不修改；其“统一路径解析”通过扩展共享解析入口、由前端提供平台目录来满足，不在 Kotlin 新写一套码表相对路径算法。

## 2. 统一术语

| 术语 | 含义 |
| --- | --- |
| 输入能力 | 形码检索、英文补全、拼音检索、原文输入等，不等于一个界面按键 |
| 基础模式 | 用户持续使用的主形码或英文模式，普通提交后仍保留 |
| 临时会话 | 覆盖基础模式的一次性输入；完成或取消后返回进入前的基础模式 |
| 输入轮次 | 从空预编辑到一次提交/取消；结束轮次不必退出基础模式 |
| 预编辑 | 尚由输入法管理、可继续修改的文本；不是候选菜单、标签或反查提示 |
| 宿主 | 当前编辑文本的应用与输入框 |
| 运行时快照 | 一致版本的配置投影、主表、辅助表、合并用户词库与索引；不包含可变输入缓冲 |
| 会话版本 | 一次状态变更的版本；与编辑器标识、运行时版本共同用于拒绝过期结果 |
| 行为配置组 | 一组确定的输入规则。LegacyV1 保持现有 Windows 行为，TouchV1 提供本文约定的手机行为；它们不是平台系统调用 |
| 平台适配层 | 将键盘/触摸及宿主回调转为共享动作，将编辑计划转为 TSF / InputConnection 调用 |

## 3. 职责总表

| 事项 | 共享 Rust 核心 | Windows 前端 | Android 前端 |
| --- | --- | --- | --- |
| 码表格式与检索 | 解析、验证、排序、去重、音节边界、万能键、反查 | 提供文件定位上下文 | 将资源/URI 导入私有目录，提供文件定位上下文 |
| 用户词库 | CRUD、冲突与覆盖规则、主表合并、持久化结果 | egui 编辑及桌面文件对话框 | Compose 编辑及系统文档选择器 |
| 模式 | 基础/临时生命周期、可用性、切换与缓冲处置规则 | 开关 compartment、语言栏、入口键和菜单映射 | 中英按钮、临时拼音入口与键盘布局 |
| 输入事件 | 解释语义动作，统一选词、上屏、顶字、取消、退格 | VK/HKL、Shift/CapsLock、系统组合键、快捷键优先级 | 触摸、长按、重复键、硬件键盘映射、输入类型识别 |
| 标点 | 执行符号提交/缓冲规则；维护共享可选标点映射表 | 保持当前映射和快捷键/模式语法优先级 | 选择中文/英文/数字符号布局；发送明确的符号意图 |
| 候选 | 稳定结果、窗口查询、候选标识、结构化提示 | 数字标签、GDI 绘制、定位/DPI/避让 | 横向候选栏、展开列表、滚动、触摸命中 |
| 预编辑/提交 | 生成编辑计划、确认结果、保持状态一致 | TSF edit session、range、显示属性、撤销语义 | InputConnection、EditorInfo、编辑器动作 |
| 生命周期 | 清空、恢复、作废旧结果及模式返回规则 | TSF 激活/失焦/composition 终止 | onStartInput/onFinishInput、连接更新、服务销毁 |
| 配置 | 默认值、共享字段解析、校验与运行时投影 | 桌面字段编辑与热键冲突校验 | 手机 UI 配置和有效共享字段编辑 |
| 路径与加载 | 相对引用解析、数据验证、快照构建、错误分类 | DLL/exe/AppData 发现、notify、AppContainer ACL | filesDir/assets/SAF、主动通知更新、应用生命周期 |
| 并发 | 只读快照共享、每会话可变状态、版本校验 | TSF 线程约束、ArcSwap 发布与 GDI 渲染线程 | 串行事件队列、后台加载、主线程宿主调用 |
| 日志/性能 | 结构化错误及耗时数据，不记录正文 | 文件日志、桌面基准与 TSF 调试 | logcat、崩溃诊断、设备性能与内存测量 |
| 安装/分发 | 无 | TIP、COM 注册、Velopack | 输入法启用引导、APK/签名/系统兼容 |

核心不得引用 Win32、JNI、Android Context、Compose、egui、GDI 或平台光标坐标。Windows 设置层中的列表筛选、表单草稿等保留；可跨端的引用校验、另存规则、文件写入结果才提取。

## 4. 接口改造清单

| 现有入口/结构 | 改造后的职责 | 兼容要求 |
| --- | --- | --- |
| `InputEvent::Char/Symbol/Select` | 增加明确的编码字符、字面文本、符号、候选选择动作，消除数字歧义 | 旧事件通过 LegacyV1 映射继续可用，不让 Windows 调用点一次性全部改写 |
| `StateMachine::handle/would_consume` | 推进与只读预判共用路由规则；新增语义模式/生命周期动作 | 预判不得加载文件、改变状态、重复提交或执行完整检索 |
| `InputMode::{Main,Menu,Pinyin,English}` | 基础模式 + 可选临时模式；菜单作为展示状态，和可提交候选区分 | 旧菜单显示、编号、不可用提示及取消行为不变 |
| `TemporaryTables::load` | 按能力加载辅助资源，不由入口键决定是否有能力；返回可用性与诊断 | 旧加载入口保留 LegacyV1 的关闭/冲突/降级语义 |
| `Transition` | 规范化为编辑计划 + 会话视图 + 处理结果 | 过渡期提供旧 Transition 映射；同一事件只走一条生产执行路径 |
| `candidates/page/total_pages` | 共享结果集窗口与候选身份，不绑定单页数字标签 | 保留旧页大小 1～10、页号和选词结果；手机可查询更多窗口 |
| `commit_current/commit_raw_current/reset` | 明确区分提交首选、提交原文、清轮次、退出临时会话、重置宿主会话 | 旧 reset 仍保持 Main 语义，不直接改为持续模式 reset |
| Windows `InputSession` | 提取纯会话协调规则；TSF 操作、主题、anchor、GDI 发布留在 Windows | 保留当前故障分支与返回的 consumed，不泛化成一套新默认行为 |
| Windows `RuntimeSnapshot/merge_dictionary` | 共享快照构建、用户覆盖、主表原始数据与反查分离 | 主表 YAML、用户覆盖排序、辅助失败策略与旧行为一致 |
| `Config` | 从现有磁盘结构投影 EngineOptions 和平台选项 | 不重命名旧字段、不更改默认、不暗中启用无效字段 |
| `config_path` | 统一解析入口接收目录上下文；平台负责取得目录 | 保留现有无参数/desktop 兼容入口和 Windows 发现优先级 |
| `TableEditor::save_to` 等 | 提取共享数据校验、引用重定位与结构化保存结果 | 不把 egui 状态或窗口逻辑移入核心；保持跨目录另存目标 |
| 用户词库 C-ABI | 保留已有符号并增加版本化的会话/资源接口 | 不更改已有函数的内存释放约定 |

## 5. 语义事件与结果契约

以下为概念接口，不要求每个动作都是独立公开函数。应以一个会话 dispatch 接口和少量只读查询封装规则。

| 动作 | 明确定义 |
| --- | --- |
| `InputCode(char)` | 一个实际编码字符；不因字符是 1～9 自动变成选词。旧数字规则由兼容映射表达 |
| `InputText(char, intent)` | 手机实际字符入口，intent 区分正常输入与强制字面输入；正常输入由核心按当前模式、主表 charset/万能键及拼音语法路由，前端不复制字符分类规则 |
| `InputSymbol(char)` | 已确定的符号；核心决定结合当前缓冲提交、保留或不处理 |
| `InsertLiteral(text)` | 直接文本输入（数字面板、固定符号、表情等），不做码表查询；先按当前规则解决旧预编辑，再提交文本 |
| `SelectCandidate(query_revision, candidate_id)` | 选择确定版本的候选；过期/越界返回明确结果，不误选同位置新候选 |
| `CommitPreferred / CommitRaw` | 分别提交首选（无候选则原文）和原文；空缓冲语义由行为配置组决定 |
| `Space / Enter` | 业务语义，按当前模式解释；空缓冲可返回不处理给平台执行空格/换行/发送 |
| `Backspace / Cancel` | 优先修改/取消输入法管理的预编辑；无缓冲时按模式退出或交给宿主 |
| `MoveCandidatePage / CandidateWindow` | 前者改变旧分页视图，后者只读获取结果窗口，均不改排序/提交规则 |
| `SetBaseMode / BeginTemporary / EndTemporary` | 明确目标、可用性与旧缓冲处置，见模式表；重复请求幂等 |
| `OpenModeChooser / ChooseMode / CloseModeChooser` | 旧 Windows 菜单的显式兼容动作；选择器是会话中的非文本展示状态，不是基础模式或可提交候选，手机直达入口不经过它 |
| `SetInputGate` | 宿主允许输入法处理或旁路；Windows 英文旁路不等于英文检索模式 |
| `ContextChanged / HostTerminated / ApplyRuntime` | 平台通知事实，核心根据行为配置组结束会话、作废结果或应用新快照；控制事件的优先级见 §8.4 |
| `Recover` | 为仍有所有权的旧预编辑生成清理计划，保持删除/保留意图；不重放文字提交，见 §8.4 |

结果必须区分 `Handled`、`NotHandled`、`Rejected(reason)`，以及模式不可用/候选过期等原因。Windows 的旧无效编号在主模式透传、临时模式消费的差异由兼容映射保留；手机点击失效候选不插入数字。

`NotHandled` 不等于“丢弃”：Windows 保留原始按键信息交给系统；手机虚拟键没有原始 OS 按键，必须明确执行宿主删除、空格、换行或 EditorAction。平台不根据中文字符串猜测结果。

第一版编码输入逐字符处理，不新增任意粘贴文本的自动分词语义。多字符字面文本允许 Unicode，并设长度上限；不是用循环调用假按键实现文本粘贴。

TouchV1 正常输入时，主表声明的数字、符号和万能键优先进入编码，再考虑中文标点转换或字面插入。数字/符号面板也走 `InputText`，不能一律发送 `InsertLiteral`，否则自定义形码无法使用这些编码。只有明确的字面操作或受限输入上下文绕过编码。Windows 继续按现有 key_filter 的转换顺序映射，不能为手机新增的字符优先级重排桌面流程。

共享 `would_handle` 是纯查询；这个要求不等于整个 Windows `OnTestKeyDown` 必须无副作用。现有 TSF 回调在查询前会进行 `prepare_context`、运行时同步、Shift 追踪与 `recover`，迁移必须保持这些准备工作的顺序和结果。核心纯查询的测试与 Windows 完整回调轨迹分别验收。

## 6. 模式及手机行为基准

### 6.1 基础模式与临时会话

- 基础模式为 Main（选定主码表，通常为形码）或 English（英文补全/原文）。旧 Windows 主表若使用合法的 `type: pinyin`，仍沿用其既有主模式行为，不因新名称强制拒绝或自动转为临时拼音。临时能力首版为 Pinyin，保留现有一次性 English 的兼容能力。
- 临时会话保存返回模式，只允许一层，不递归叠加。重复打开同一空临时模式不丢状态；有缓冲时切到另一临时模式按切换规则先处置。
- `clear_composition` 只结束轮次；`end_temporary` 还退出临时覆盖；`reset_context` 清除所有旧输入框相关状态。三者不能继续共用一个无语义的 reset。
- 能力描述返回 `available`、`candidate_support`、`reason`。无拼音表时禁用拼音并说明原因；英文未配置词表可以原文输入。
- 手机英文配置了损坏词表时，明确显示补全不可用但保留原文键盘；Windows 临时英文保持当前“配置错误则不可进入”的行为。热重载失败均先保留已有可用快照。
- 先验证切换目标可用，再生成处置旧缓冲的计划。重复请求当前模式一律无操作，不因非空而提交/清空；切到另一可用临时模式时取消本轮临时预编辑、保留最初返回模式。退出临时模式默认取消，提交必须使用明确的提交动作；目标不可用不丢缓冲、不上屏。
- LegacyV1 的兼容层保存模式选择器状态，将旧入口键、1/2、Backspace/Esc 映射到选择器动作，并继续向旧调用方呈现 `InputMode::Menu`。选择器项由核心能力描述生成、标签由前端绘制；其他按键仍按旧菜单消费规则处理。进入空菜单时的 composition 清理与取消行为也纳入旧轨迹，不用“菜单在前端”省略它们。

### 6.2 行为对照

TouchV1 是首版默认方案；后续产品调整须修改此契约与测试，不扩散成 Kotlin 私有分支。

| 场景 | LegacyV1 / 现有 Windows | TouchV1 / Android 首版 |
| --- | --- | --- |
| 主形码 | 现有编码/大小写/万能键/自动上屏/顶字规则 | 相同核心规则；软键盘负责输入字符，不擅自将编码转小写 |
| 进入临时模式 | 空主缓冲下入口键打开菜单，再按 1/2 | 专用拼音入口直接发语义动作，不要求配置入口键 |
| 从非空基础缓冲进入临时模式 | 入口字符按原主模式处理，不进入 | 先提交原文，成功后进入；失败不切换 |
| 切换基础中/英文 | 主缓冲原文提交；临时输入取消；英文是实体键旁路 | 基础缓冲原文提交；临时缓冲取消；英文进入持续补全；成功后切换 |
| 临时模式提交/取消后 | 返回 Main | 返回进入前基础模式，包括 English；不得恢复之前已提交的缓冲 |
| 形码空格/回车 | 空格首选/原文；回车原文；空时放行 | 非空同 Windows；空时由宿主插空格或执行回车动作 |
| 临时拼音空格/点击 | 首选或所选词，无尾随空格，退出临时模式 | 相同；点击携带候选身份 |
| 临时拼音回车 | 非空原文提交，退出临时模式；空时消费但不提交 | 同；非空提交这次不执行发送，退出到基础模式后的空缓冲回车才执行宿主动作 |
| 空临时模式的空格/回车 | 留在临时模式，无文本和宿主动作 | 同，不能误发送；用退格或取消退出临时模式 |
| 持续英文空格 | 不适用；现有临时英文不补空格且退出 | 首选或原文提交并加一个 ASCII 空格，仍在英文；空缓冲插一个空格 |
| 持续英文点击候选 | 不适用 | 仅提交候选，不自动补空格，仍在英文；用户可再按空格 |
| 持续英文回车 | 不适用 | 非空先原文提交且不发送；空时交给宿主动作 |
| 持续英文标点/数字 | 临时英文标点入缓冲，数字为选词 | 标点和数字先提交当前原文，再插入该字符并开始空轮次，绝不当候选编号；不做自动纠错/首字母大写 |
| 空临时模式退格 | 退出；有内容先删字符，删空仍保留模式 | 同；持续英文删空后仍保持英文，再退格删除宿主字符 |
| 切到数字/符号面板 | 不适用 | 只是布局变化，旧预编辑保留；主表声明字符继续编码，真正字面输入按下面规则处置 |
| 形码中插入字面文本 | 保持原有桌面符号处理 | 形码有候选先首选、否则原文，再插字面文本；临时拼音/英文及持续英文先原文再插入；完成临时轮次后恢复基础模式 |
| 失焦/输入框切换 | 主模式结束但保留宿主预编辑；临时模式删除预编辑 | 结束旧连接：基础模式尽力完成原文预编辑，临时模式取消；连接已失效则只作废本地状态，不向新框补写 |
| 成功运行时更新 | 主模式保留宿主文本、临时模式删除，清旧候选 | 同样清轮次并更新能力；保留可用基础模式，失效模式回 Main 并提示 |

手机持续英文保留大小写，补全按词表既有匹配规则，不新增不区分大小写搜索。英文词组内部空格保留；空格动作额外添加的分隔空格与词条内部空格是两回事。

手机基础模式选择在同一次服务生命周期的普通文本框之间保留，临时模式和预编辑不跨输入框保留；进程重启首版回到 Main，不自动恢复未完成输入。数字/电话/密码等字段的受限输入策略是当前输入上下文的覆盖，不改写用户的基础模式选择，返回普通文本框后恢复该选择。进入受限字段先作废旧输入会话；对已经断开的旧连接只清本地状态。

“临时拼音可用”只指当前全拼/前缀和边界算法，不意味着简拼、模糊音或句子模型。Android 硬件键盘采用明确的按键映射表；普通系统组合键在有无缓冲时均不被软键盘规则吞掉，输入法专用快捷键单独定义。这里只共享已归一化的动作，不把 Android 键码解释放进核心。

## 7. 候选、提示与性能接口

- 输出结构包含 `query_revision`、总数、窗口偏移、候选数组及可用模式。候选含稳定的窗口无关身份、提交文本、匹配类型和提示数据；编号、颜色、坐标由前端生成。
- `query_revision` 至少关联会话、缓冲和运行时版本；即使文本相同，重载后旧点击也不得命中新候选。
- 区分输入会话 generation、查询 query_revision 和展示 view_revision。仅切页/滚动更新展示版本，不必让同一查询的稳定候选 ID 失效；字符、模式、运行时或编辑器变化必须使旧查询失效。Windows 页内编号按当前旧分页映射为候选身份，手机窗口查询是只读操作。
- 查询结果按既有顺序去重后再分页；不能为优化第一屏先截断再排序，也不能在 Kotlin 二次排序。
- Windows 页大小仍按旧 `candidate_count` 1～10；Android 展开使用有上限的窗口查询，不为了多显示候选修改旧字段范围。限制查询窗口与 JNI 返回量，首次实现可沿用全量检索，不承诺提前完成渐进检索优化。
- 编码后缀提示、主码反查、不可用原因分开表达；菜单项不是词条，提示不是提交文本。
- 反查保持“原始主码表、整词精确查找、去重、短码优先”的规则，不由用户合并词库生成。
- 当前临时模式不受主模式 show_code_hints 控制的行为保留；手机显示开关只影响提示展示，不改变候选身份、排序或上屏。
- 会话视图还需包含预编辑类别、可见状态和“视图不变”的结果。Windows 当前主模式候选/顶字用 Converted，临时预编辑和无候选编码用 Input；`Transition::None` 保留旧视图。不能让仅有 `SetPreedit(text)` 的接口丢失显示属性，也不能失败后提前发布新候选或覆盖已有 anchor。
- 性能测量分开记录检索、快照构建、JNI 转换、UI 刷新和宿主提交；先测真实码表与宽前缀，再决定缓存策略。

## 8. 会话与宿主编辑确认

### 8.1 建议公开接口

| 接口 | 契约 |
| --- | --- |
| `RuntimeBuilder::build(resources, options, load_policy)` | 后台读取/校验并生成不可变快照和诊断；无宿主/UI 副作用 |
| `Session::new(runtime, behavior_profile, context)` | 每个输入会话拥有缓冲与模式；词表用 Arc 共享 |
| `Session::would_handle(action)` | 只读预判；不发起编辑，不加载文件，不完整检索 |
| `Session::prepare(action)` | 返回唯一 token、候选/状态预览与有序编辑计划；TouchV1 有待确认计划时返回 Busy；LegacyV1 通过同步兼容驱动保留现有回调重入语义，见 §8.4 |
| `Session::acknowledge(token, outcome)` | 根据宿主结果提交状态/回滚/进入清理态；重复或旧 token 不重复生效 |
| `Session::snapshot / candidate_window` | 只读已发布视图和候选；另提供适配所需的处理状态，不混用候选预览；不触发提交、推进模式或懒加载 |
| `Session::invalidate_context` | 宿主切换/终止可打断待确认计划，提升 generation，旧 ack 无效 |
| `Session::recover / close` | 显式恢复旧预编辑或结束会话，允许在清理态调用；关闭作废未执行计划，释放仍在执行操作的引用须等待其退出 |

无宿主编辑的动作仍通过同一序列确认，可由 Rust 内部一次完成；JNI 调用次数不必机械增加。纯资源管理与用户词库编辑为独立接口，不能借会话字符事件调用。

### 8.2 编辑计划

计划表达 `SetPreedit(text, kind)`、`CommitComposition(text)`、`FinishPreedit(keep/delete)` 和“提交后开始下一预编辑”的有序组合。提交目标明确为 `OwnedComposition` 或 `CurrentSelection`；仅 LegacyV1 适配允许保留旧带长度的 fallback，需逐项验证，Android 不得照搬。不要让核心返回“向左删 N 个未知字符”。

一次顶字可产生“提交旧词 → 新预编辑”。适配层记录每一步是否完成，反馈最后完成步骤及未确定步骤；不能把多次宿主调用当成数据库事务。菜单/模式文字不能作为 SetPreedit 的正文。

结果至少区分：

| 宿主结果 | 核心处理 |
| --- | --- |
| Applied | 确认计划状态后发布候选和模式；不再次编辑 |
| RejectedBeforeWrite | 只有适配层确定尚无文字副作用时才使用；按配置组决定回滚或清理 |
| PartiallyApplied | 记录已完成步骤，严禁重放已上屏文字；清理剩余预编辑 |
| OutcomeUnknown | 超时、连接失效、无法确认结果；不重放文字，不把失败猜成“未写入” |
| StaleContext | 忽略旧结果，禁止向新编辑器执行旧计划 |

LegacyV1 只在现有 `handle` 处理临时模式且有 rollback 快照时允许安全重试；`set_chinese`、`lose_focus`、`reload` 并没有同样的 rollback，不能因它们涉及临时模式就自动恢复原输入。TouchV1 在确认未写入时可保留当前输入供重试，其余进入清理态。清理失败保留“删除/保留预编辑”的原意，不因下一次调用变成相反操作。

Windows `EditFailure::retry_safe` / `text_committed` 可先映射进结果模型；Android 不能仅凭一个 false 返回值就断言远端没有发生任何修改。适配层无法证明时用 OutcomeUnknown。

### 8.3 时序、并发与文本单位

- TouchV1 一个 Session 串行处理动作，最多一个未确认 token。Windows 宿主调用在核心锁外，既有同线程回调可能重入，LegacyV1 不得因新增“单个 pending”限制拒绝原路径可处理的事件；按 §8.4 保留兼容时序。
- token 绑定编辑器标识、会话 generation 和 runtime revision。宿主调用前与结果发布前都校验；调度层在执行前取消过期任务。不能仅在返回后丢结果却已把文字写入新框。
- 当前 Windows 明确使用 `TF_ES_SYNC | TF_ES_READWRITE` 并检查请求与执行 HRESULT；本次不改异步调度。一个既有 EditSessionOp（包括顶字）仍在同一 edit session 执行，不把每个抽象步骤拆成新请求，避免改变撤销和回调时序。Android 由串行输入队列维持顺序，加载与索引构建在后台，InputConnection/Compose 更新回主线程；不能把每个键独立启动协程并任其乱序完成。
- Rust 文本内部为 UTF-8；跨语言协议明确 UTF-8 字节长度，平台 range/selection 使用平台要求的单位并显式转换。已有 `replace_len` 来自 Rust scalar count，不能直接作为 Android UTF-16 长度。
- Windows 保留既有 composition range 优先的适配逻辑；旧 fallback 长度语义在迁移测试中单独刻画。若发现非 BMP 边界缺陷，先记录为独立修复，不能在架构重构中无记录地改变编辑范围。
- 核心编码退格维持逐 Unicode scalar 的既有语义；Android 删除宿主文本需正确处理选区、代理对和组合字符，不能用字节长度删除。该删除适配不是形码检索算法。

### 8.4 恢复、控制事件和可观察时序

共享处理状态至少区分 Ready、AwaitingAck、NeedsCleanup、Closed；AwaitingAck 不自动代表所有配置组都拒绝重入。Busy 是手机暂不能处理的调度结果，不等于普通 `NotHandled`：手机将后续动作保留在有界、有顺序的队列并可见报告拒绝，不能掉键或把同一个键既提交又交给宿主。Windows 保持现有同步调用；清理失败时维持旧“不拦截本次键”的返回，不引入新的异步键队列。

LegacyV1 通过同步兼容驱动处理旧路径允许的同线程重入：每个在途调用持有自己的编辑计划/token，较新事件推进 generation，旧调用返回后不覆盖新状态或候选。不能把它改成 Busy 后直接透传，也不能阻塞等自己的 COM 回调退出。CP-01/08 要对嵌套控制事件及嵌套输入做差分故障注入；若新接口暂无法表达该行为，保留旧驱动不切换生产入口，不能用“通常不会发生”删掉该路径。

- NeedsCleanup 必须可调用 Recover。成功才恢复普通输入；失败仍保留原清理意图。不把原提交重新包装成“重试”。
- HostTerminated、ContextChanged、close 是控制事件，不因 Busy/清理态被无限排队；作废旧 token 后不再执行旧计划。旧连接仍有效时，可用绑定旧连接的清理计划结束它；已经失效或失去预编辑所有权时只清本地状态，不对新的选区执行 delete。
- OutcomeUnknown 只在确认仍拥有同一预编辑范围时允许清理；无法确认时保留宿主文字、作废本地状态，不能以防重复为名误删已提交文本。LegacyV1 的既有 composition 对象与恢复轨迹仍按兼容适配执行。
- TouchV1 在当前编辑确认后应用等待中的最新运行时更新；销毁/换宿主先作废当前 token。LegacyV1 按现有 runtime 同步回调的实际时点接纳新 revision 并增加 generation，不能统一延后到 ack 之后。
- 销毁中的句柄禁止新请求；已进入的调用持有会话/快照引用直到返回，待发送编辑任务先取消。不能先释放对象，再等待携带裸指针的回调返回。

**Windows 处理状态与候选发布时机必须分开。** 当前 `handle` 在宿主调用前推进状态机；`set_chinese` 先改变 chinese 开关；`reload` 先替换状态机/config/revision；候选视图则在成功且 generation 未过期时发布。新接口必须允许 LegacyV1 保持这种可重入时序，不把 Applied 表误读成所有内部状态都必须等 ack 才能变更。切换/重载清理失败不回滚已经接纳的开关或运行时；只有 TouchV1 的主动模式切换采用“处置旧缓冲成功后才切换”。

### 8.5 宿主能力和预编辑所有权

上下文携带稳定的编辑器 identity/epoch、输入用途、是否可预编辑、是否可获得有效选区/周边文本，以及宿主动作描述；核心只读标准化能力，具体 Android/TSF 枚举留在前端。同一输入框的 View 重建不自动等同于新输入会话；若无法确认连接连续性则开启新 epoch，并拒绝旧编辑。

Android 对明确不支持 composition、但支持插入的宿主，可从本轮开始就选用“候选栏本地预编辑、提交时替换当前选区”适配模式。已经调用失败且结果未知时不能立即改走直接插入重试，以免重复上屏。不能提供可靠编辑时显示不可用，不做盲目删除/按键模拟。密码/数字等直接输入上下文不创建候选预编辑。Windows 不引入这套新降级行为，保留已有 range fallback。

## 9. 运行时、配置、路径和持久化

### 9.1 运行时快照

共享构建器接收配置与资源清单：主表、可选用户词库、辅助表、路径上下文、行为配置组。保留原始主表供反查，合并后的表供主检索；用户同 `(code, word)` 覆盖系统权重，其他系统条目保留。

启动策略和重载策略分开：Windows 维持当前配置/主表/用户表失败后的既有回退路径、辅助失败时主表可用等行为；不得将所有初始化错误简单改成相同空表或终止进程。Android 首次安装准备内嵌完整默认表，损坏时明确报告并提供恢复，保留字面输入能力。加载失败、快照发布和会话采用新 revision 是三个阶段；构建成功后才可发布，但 Windows 会话采用后清理失败不撤回新 revision。

新增 Android 初始化及两端重载均在后台构建；当前 Windows 初次加载入口的线程和触发时点保持，不能把“后台加载”普遍化而让 DLL 激活后第一批键落到未就绪空引擎。Windows 重载失败保留旧快照、诊断和下一次重试所需路径；Android 同样保留已有可用快照，并显示更新未应用。空的拼音引用表示能力未配置，不是全局加载失败；英文空引用允许原文模式；配置了非空但失效的引用才按配置组产生加载错误。

共享构建器返回资源依赖清单及失败的新引用位置，由 Windows 既有 watcher 决定监听；Android 主动更新不模拟 notify。构建与发布不能反向调用 UI 或宿主编辑。

Windows notify 与缺失目录监听不迁入核心。Android 设置保存/导入后主动请求构建，服务启动检查磁盘版本，不依赖 Activity 与服务必然同时存活。更新请求带序号，较早完成的旧请求不能覆盖较新结果。

Android 振动、键盘高度等仅前端设置变更不重建引擎或取消预编辑。Windows 对现有有效配置文件重载的清理行为仍保持，不为这次拆分顺带优化成不同语义。

快照只读共享，缓冲不共享；不在每次按键创建引擎/词表。发生内存回收可以释放非活动快照，重新加载期间不能在按键线程同步读大词表。

### 9.2 配置兼容

- 继续使用现有 `config.toml` 和 `.dict` YAML；先添加内存投影 `EngineOptions`，不迁移/重命名用户文件。
- 共享生效字段：主表与用户词库、enable_user_dict、自动上屏、顶字、显示提示等。候选数、外观、快捷键按用途投影到前端。配置字段是否生效以 [现状记录](android-readiness.md) 为准。
- `commit_mode`、`punctuation_mode`、`enable_exact_match`、`enable_fuzzy`、`toggle_simplify` 等保留旧值与旧实际行为，不在本系列顺带激活。
- 手机键盘高度、振动、布局等放入独立 Android 前端配置文件（如 `android-ui.toml`）；引擎配置只有一个真源，不再复制一份到 SharedPreferences。
- 辅助引用继续读取主表现有 `temporary.pinyin_table/english_table/reverse_lookup`。`temporary.key` 保留为旧桌面入口元数据；手机通过显式能力加载计划请求资源，无须伪造入口字符。
- 校验分成数据语义、使用场景与平台映射三层。Windows 仍检查临时键与快捷键冲突；Android 不因未使用的桌面快捷键冲突而禁用拼音或无法保存其他字段，但保留该诊断，不默改桌面配置。新入口必须显式传入校验场景，不能直接复用总是调用 `validate_for_save` 的旧 `Config::save`。
- 本阶段不新增公共磁盘字段解决仅手机 UI 的问题。如后续确需共享新字段，先定义缺省、版本和兼容规则，同时更新核心结构及两端编辑界面；旧版本会丢未知字段的问题不能靠 serde 默认值解决。

必须刻画并保持以下 Windows 校验差异：`Config::load` 仅验证基本字段，保存另检查快捷键重复；运行时在临时入口关闭时不加载辅助引用，设置编辑器保存配置了非空引用的码表时仍验证引用；设置保存先做配置与上下文预检，再按需写码表，最后写配置。统一代码并不意味着统一这些场景的拒绝条件或先后顺序。

### 9.3 路径、导入与保存

- 共享解析器接收 `StorageContext`，表达桌面便携/配置目录或应用私有目录。Windows 设置程序仍使用 exe 目录，TSF 使用 DLL 目录和带 `KF_FLAG_DONT_VERIFY | KF_FLAG_NO_PACKAGE_REDIRECTION` 的 Roaming 获取方式；便携判断不依赖 Roaming 查询成功。不能统一替换为宿主 exe 或普通 dirs 调用，现有 ACL 准备仍留在设置程序。Android 提供 filesDir，不探测进程可执行文件目录。
- `resolve_resource_path` 与主表相对辅助引用规则复用；不把 `content://` 当 PathBuf，不把 `C:\...` 当 Android 可访问路径。
- Android 从 SAF 取得流，在私有暂存区写入完整包并验证。相对引用随包目录保留；外部绝对引用需用户选取对应资源后显式重绑定；缺失时提示，不按同名文件猜测。
- 首版“码表包”指一个显式选定的主 `.dict` 与其直接引用的文件集合，可来自系统选取的目录或多文件选择；主表必须由用户指定，不猜测多个 `.dict` 中哪一个是主表。单表无辅助引用时可独立导入；有引用必须补齐或明确移除。首版不额外设计 ZIP 格式，也不递归加载辅助表自己的引用。
- 内嵌码表首次复制只补缺失资源；升级不覆盖用户修改的表。更新模板与用户活动表分离，并保留数据来源/许可证文件。
- 配置、码表、用户词库保存都报告成功、失败及部分成功；单文件采用同目录临时写入与替换。多文件保存不伪称整体原子事务；Windows 维持“表已保存、配置失败”的提示与 dirty 状态。
- Android 导入包按完整目录验证后再切换活动引用，失败不覆盖旧可用包；所有路径限制在选定导入根内，拒绝越界引用。
- Android 新包先写到独立版本目录，构建器基于最终目录验证并生成快照，再原子切换持久化的活动配置引用，随后发布运行时。崩溃发生在切换前则旧配置仍有效；切换后重启按新配置重建，若发布失败报告“已保存、尚未应用”。同目录版本不可原地覆盖；旧包在仍被磁盘引用或存活快照使用时不回收。单文件 rename 不等于整个包/运行时事务，不能只记录内存激活结果。
- 新增 Android 设置与服务的写请求串行化，导入/词库编辑使用基于版本的冲突检测，防止后完成的旧草稿覆盖新数据。具体锁/原子替换机制由平台存储适配提供，共享规则判断冲突。Windows 旧调用使用显式兼容写入策略；新增冲突提示不在本系列默认启用。
- 用户词库第一版沿用现有编码和内容约束，不自动扩展成拼音学习库，也不把用户数据写回内嵌主表。主表、辅助表的类型/长度/引用校验使用同一核心实现。

### 9.4 数据管理接口

共享数据操作与输入会话分开公开，第一版至少覆盖以下操作。调用方持有 UI 草稿，核心接收数据与期望版本；不以一个任意文件路径加任意操作字符串组成万能接口。

| 操作组 | 输入与输出契约 |
| --- | --- |
| 配置读取/校验/保存 | 返回既有配置及生效字段诊断；新调用保存带期望文件版本，旧 Windows 调用显式选择兼容写入策略，返回新版本或适用的冲突/写入错误 |
| 码表读取/验证 | 返回元数据、词条和结构化问题位置；列表窗口/筛选与编辑草稿可由前端维护，但格式校验不可复制 |
| 码表保存/另存 | 接收原位置、目标位置与草稿；共享规则计算辅助引用重定位并校验；成功才更新活动文件身份 |
| 资源包检查/激活 | 检查主/辅助引用完整性、类型与根目录约束；激活只在完整检查和运行时构建通过后发生 |
| 用户词库读取/增删改 | 沿用现有重复词条与编码限制；新接口带文件版本和词条身份，避免旧行号删除了刷新后的另一项 |
| 用户词库导入/导出 | 保留现有同 code+word 覆盖权重规则；返回新增/更新结果和错误；外部 URI 的读写仍由 Android 转为流或暂存文件 |
| 保存与运行时应用 | 返回 Saved、PartiallySaved、Conflict 或 Failed；磁盘保存成功与运行时应用成功分开报告，不把加载失败误称保存失败 |

文件版本应能识别外部修改（例如内容摘要与管理代次），不能只用内存计数或低精度时间戳。版本检查和写入须在本应用共同的写入序列内执行；这不构成对不遵守该序列的外部编辑器的原子 CAS 承诺。Android 私有活动包采用受管写入口，外部修改通过显式导入；Windows 保留旧保存行为，不在本系列默认启用新增冲突拒绝。

## 10. C-ABI / JNI 与模块落点

建议的模块职责（名称暂定）：

| 位置 | 内容 |
| --- | --- |
| `core_engine` | 纯 Rust 语义动作、会话、快照构建、候选、配置投影与数据规则；复用既有 dictionary/pinyin/user_dictionary |
| `core_engine` 的 FFI 模块 | 无平台依赖的版本化 C-ABI，对外导出生命周期与输入协议；保留已有用户词库符号 |
| `windows/im_engine/input_session` | 迁移后只保留 Windows 行为配置、TSF 编辑结果映射与 GDI 视图适配 |
| `windows/im_engine/key_filter/text_service/reload` | 实体按键、COM/TSF、坐标、宿主编辑、notify 与生命周期 |
| `windows/settings` | egui 表单、草稿与文件对话框；调用共享校验/保存规则 |
| `android/native` | 独立 JNI crate，依赖 core_engine，产出 Android `.so`；JNI 类型不进入 core_engine |
| `android/app` | Kotlin InputMethodService、InputConnection adapter、Compose 键盘/设置、存储与安装引导 |

Windows 直接调用 Rust 接口，不绕 JNI/C-ABI。JNI 可以直接包装同一 Rust facade，C-ABI 和 JNI 共用协议转换规则与契约测试；不再实现两个状态机。

桥接要求：

1. 新版本引擎/快照与会话分别建销；新句柄携带类型与代次并验证，禁止把任意 jlong 直接当合法 Rust 指针。销毁后调用、重复销毁、错误会话必须返回可识别错误。旧 `mywubi_user_dict_*` 仍是原有裸指针 ABI，保留其“有效指针、仅释放一次”调用方契约；新安全句柄不得冒充旧指针，不能针对旧 ABI 做违反安全契约的双重释放测试。
2. ABI 明确版本、固定宽度整数、动作 tag、长度与错误码。输出使用 UTF-8 buffer + 长度及成对释放函数，不暴露 Vec/String/enum 布局，也不靠 NUL 判断任意文本长度。带长度的协议允许文本中存在 NUL，但具体词库字段仍按既有规则拒绝；不得把这一能力强加给旧 NUL 结尾用户词库 ABI。
3. 创建、动作分发/确认、Recover/关闭、状态/候选读取、运行时替换、销毁覆盖完整输入流程；另导出 §9.4 的配置与资源管理操作，CP-11 因此依赖共享数据管理完成。不能只导出 search，让 Kotlin 拼接输入规则。
4. 输入大小、窗口大小和数值范围可验证；可检查的空指针/长度组合、非法 UTF-8、非法动作返回错误。非空外部指针所指内存有效期仍是 C 调用方的安全契约，不能宣称可验证任意野指针。FFI 捕获可展开 panic 并返回错误，不能宣称捕获 OOM 或 abort。
5. JNI 在所属线程使用 JNIEnv，局部引用及时释放；Java 字符串通过正确转换得到 Rust UTF-8，不把 Modified UTF-8 当普通 UTF-8。不得向 Java 借出随下一事件失效的 Rust 内存。
6. 首版协议可使用一个有版本的有界 DTO buffer 承载动作/结果（如 UTF-8 JSON），减少 JNI 调用面；用性能测量决定是否替换为二进制布局，不能无数据地增加复杂性。
7. Rust 核心静态/rlib 链入 JNI cdylib，再由 APK 打包 `.so`；“有 staticlib”不等于 Android 可直接加载 `.a`。
8. 新 workspace member 必须保持 Windows `cargo test --workspace` 可用；JNI 导出和依赖按 Android target 隔离，协议测试在主机执行。
9. Rust、C-ABI 与 JNI 使用同一组协议样例和语义轨迹进行等价测试；绑定版本不匹配在初始化时拒绝，不能静默解释未知动作。每次调用自己的错误对象/缓冲明确所有权，避免进程全局 last_error 在并发会话间串错。

## 11. Android 适配要求

- InputMethodService 与配置 Activity 首版同进程、共享资源管理入口；服务存活不依赖设置 Activity。真实输入框/连接更换更新 context identity；区分输入会话结束与仅键盘 View 隐藏/重建，不能每次重建 View 就重建词表、丢弃缓冲或重复提交。只有确认同一连接与预编辑所有权时才延续会话，否则按新 epoch 处理。服务销毁释放会话，进程被系统回收不依赖 onDestroy 持久化关键配置。
- Compose 只接收只读视图并派发动作；recomposition 不调用初始化、load、提交或词库写操作。IME View 的生命周期/保存状态 owner 与销毁策略需显式接入并测试。
- 根据 EditorInfo 为普通文本、数字、电话、密码、网址/邮件选择输入策略和布局。密码/安全字段不展示或记录敏感候选，不做用户词库写入；首版无自动学习。
- Enter 的宿主动作由适配层从 imeOptions 等解析。非空预编辑先处理本轮；只有基础模式空缓冲或直接输入上下文才能执行发送/搜索/下一项/换行，空临时模式仍消费但不执行宿主动作；避免一次点击同时上屏和误发送。
- `setComposingText/commitText/finishComposingText` 操作和 selection 更新在同一编辑器身份下执行。宿主修改选区或取消预编辑时作废旧状态；不能把输入法自己的预期回调误判为外部修改而清空下一轮。
- 删除宿主选区优先；无选区时验证 Unicode 删除。未知连接状态下停止旧计划，不能删除另一个输入框文本。
- 基本布局覆盖字母、大小写、数字、标点、退格、空格、回车、中英、临时拼音、输入法切换；长按/连删取消、横竖屏、系统 Insets、触控与 TalkBack 标签属于前端。
- 文件准备、加载、导入导出和更新验证在后台；版本化状态回到 UI。启动未就绪时显示明确状态，不把加载失败表现成“没有候选”。

官方平台依据集中于 [参考信息](android-readiness.md#5-外部技术参考)。特别注意 InputConnection 并不提供跨多次调用的原子事务；JNI 编译成功也不等于 16 KB 页大小设备兼容。

## 12. Windows 无回归的迁移原则

1. 先以基线提交固定事件轨迹和宿主编辑轨迹，再提取接口。旧分支与新分支在测试中对比，生产只执行一次。
2. 第一步保持 `StateMachine` 旧入口和 LegacyV1 默认值。新增动作/模式是可选能力，不改变现有 Windows 默认路径。
3. 数据装配、会话协调、按键映射分别迁移，各自通过验收后再进行下一步，避免一次替换整条 TSF 链路。
4. 保持 Windows 全局英文旁路；不因核心新增持续英文自动给 Windows 打开英文候选。
5. 保持旧配置、用户词库、码表格式、相对路径、DLL 发现、AppContainer 权限、COM GUID/导出和安装升级流程；不混入 TIP 重构。
6. 自动化必须比较 consumed、提交正文、预编辑、模式、候选顺序/提示、页面和错误恢复结果。仅比较最终文本不足以发现吞键或残留候选。
7. 真实 TSF 测试覆盖记事本和至少一个浏览器文本框，含切焦点、撤销、热重载及语言栏。移动端新增能力只在手机行为配置组验收。
8. 每步保持可独立回退的变更范围；出现差异先判定是回归还是既有缺陷，不修改旧预期让测试“通过”。任何必要的行为修复另列，未澄清前不切换生产调用。
9. CP-10 是 Windows 迁移阶段验收，不是永久通行证；后续 Android/JNI/资源改动若触及共享代码、依赖或构建配置，每次仍运行受影响的 Windows 自动化，发布前对最终制品重新执行完整实机验收。不能引用早期 DLL 的成功结果为后期共享变更背书。

完整行为编号、任务依赖与验证门槛见 [实施与回归计划](cross-platform-implementation-plan.md)。
