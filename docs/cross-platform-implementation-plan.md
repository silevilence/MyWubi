## 2. 阶段与进入条件

| 阶段 | 内容 | 完成门槛 |
| --- | --- | --- |
| G0 固定行为 | CP-01 | 现有事件/宿主轨迹可复现，Windows 可用基线与未知项记录清楚 |

| G4 手机能力 | CP-15～CP-20 | 字母/数字/模式/候选/编辑/设置/词库形成完整首版体验 |

CP-12 工具链验证可在 G0 后提前开展；不依赖 Android UI 完成。各分支可以在隔离改动中推进，但共享输入规则未稳定前不让 Kotlin 补写临时业务规则。不能以 Android 构建成功代替 Windows G2，也不能以主机测试成功代替真机验证。

G2 是持续条件：后续共享核心、桥接依赖或 workspace 构建变化仍须通过 Windows 回归。CP-24 必须用最终版本重新运行真实 TSF 验收，不能复用 CP-10 较早制品的结果。手机首次可运行时即具备连接身份校验和基本错误处理，CP-18 扩充故障/生命周期覆盖，不能把必要保护全部推迟到该任务。

## 4. Windows 行为不变矩阵

所有条目比较“旧基线 vs 新 LegacyV1”，而不是依据注释或新设计重写预期。当前未有充分测试的条目先补证据再迁移。

| 编号 | 场景 | 必须保持的结果 |
| --- | --- | --- |
| W01 | 普通形码、大小写、自定义 charset | 编码接受范围、大小写敏感性、无候选原文行为不变 |
| W02 | 精确/前缀、重码权重、去重、万能键 | 同一输入得到相同候选次序、文本和提示，跨页不重复 |
| W03 | 自动上屏、最大码长、溢出顶字 | 开关组合、首选提交及新一轮预编辑一致，事件不丢失 |
| W04 | 空格、回车、退格、Esc、空缓冲 | 首选/原文/透传规则不变，包括空状态 consumed |
| W05 | 数字与数字型编码/万能键 | 编码与选词优先级、无效编号主模式透传/临时消费不变 |
| W06 | 二三候选、翻页键、Shift、冲突 | 快速选择优先于翻页，临时模式空格/标点语法优先；主模式自定义空格翻页保留 |
| W07 | 标点与系统键盘布局 | 现有中文映射、已有候选首选+标点、无候选缓冲、Shift/CapsLock 字符不变 |
| W08 | Ctrl/Alt/Win、Shift 切换追踪 | 系统快捷键放行，Shift 单按可切换、组合不误切；不新增吞键 |
| W09 | Windows 中英文/语言栏 | 英文旁路、主缓冲切换提交原文、临时切换取消、compartment 同步一致 |
| W10 | 临时入口、菜单、不可用模式 | 主模式仅空缓冲进入；菜单不写入文档；入口冲突/缺失错误与当前可用性一致 |
| W11 | 临时英文 | 大小写/英文标点保留、数字选择、无尾空格、一次提交退出、缺词表原文能力一致 |
| W12 | 临时拼音 | 完整/部分边界、尾随单引号、无效音节位置、小写约束、无简拼，不继承主表自动上屏 |
| W13 | 空临时模式与退格 | 有内容删一字、删空仍保留、再次退格退出；空空格/回车不上屏标签 |
| W14 | 反查和候选显示 | 仅原主表整词反查，短码优先；主模式提示开关与临时提示行为保持 |
| W15 | 失焦、宿主终止、成功重载 | 主模式保留宿主预编辑、临时删除；候选隐藏，过期编辑结果不重新发布 |
| W16 | 提交前失败、部分成功、清理失败 | 仅已有 rollback 的临时 handle 可安全重试，切换/重载/失焦不凭临时状态回滚；清理不重放提交 |
| W17 | 无变化/失败/恢复热重载 | 同 revision 不打断；坏主/辅助/用户文件保留旧快照；新引用及缺失目录恢复可重试 |
| W18 | 用户词库与设置保存 | 相同 code+word 覆盖权重、反查隔离、无效词条拒绝、部分成功和 dirty 提示保持 |
| W19 | 配置/码表/路径兼容 | 旧文件往返、便携/AppData、DLL 路径、相对引用和跨目录另存不变；无效旧字段不被激活 |
| W20 | 宿主与系统集成 | GDI 定位/无焦点、撤销、语言栏、TIP/COM、设置 AppContainer 授权和 Velopack 构建无新增回归 |
| W21 | TSF 预检准备与同步编辑 | 保留 prepare_context、同步运行时、Shift 追踪和恢复顺序；TF_ES_SYNC 请求及错误检查不变，顶字不拆成多个 edit session |
| W22 | 开关/运行时变更遇编辑失败或重入 | 保持编辑前状态与 generation 时机；切换/重载失败不回滚；旧路径允许的同线程嵌套输入/控制事件不改 Busy/阻塞，旧调用不覆盖新结果 |
| W23 | 预编辑类别、None 与候选发布 | Input/Converted 对应分支、None 保留视图、失败隐藏/保留及原 anchor 回退一致；不提前发布计划预览 |
| W24 | 校验场景与资源关闭 | 读配置与保存热键校验不同；关闭临时入口时运行时不碰辅助表，编辑器保存仍校验非空引用；空拼音引用非全局加载失败 |

对比轨迹至少包含：输入动作及映射、consumed、模式/缓冲、候选列表/页/提示、编辑操作序列、提交正文、失败清理意图和结果发布版本。候选 ID 可以不同，但与实际候选文本和版本的关联必须正确。

## 7. 验证执行与证据

### 主机自动化

每个核心或适配步骤至少运行其相关契约/回归测试；每次 Windows 生产入口切换运行完整工作区：

G2 之后修改共享逻辑、桥接依赖或工作区构建配置，同样运行完整工作区测试/构建和受影响的 Windows 回归；该要求持续到最终验收。仅 Android 纯 UI 变更不要求重复无关 TSF 实机测试，但最终制品必须重验。

```powershell
cargo test --workspace --quiet --locked --offline
cargo fmt --all -- --check
cargo clippy -p core_engine --all-targets --locked --offline -- -D warnings
cargo build --workspace --locked --offline
```

`--offline` 仅适用于依赖已经准备好的环境；新工具链/新依赖首次获取单独完成，不把离线缓存缺失误报为功能缺陷。FFI/JNI 新包加入后增加对应主机协议测试和 Android 设备测试命令，写入构建文档。

现有工作区严格 Clippy 的历史问题按基线隔离记录，新改动不得扩大警告；不能全局放宽 lint 掩盖新增问题。测试数量允许随有效用例增加，但不能用数量替代 W/A/R/B 覆盖映射。

### 真实宿主

- Windows：使用隔离测试目录/虚拟机，记录 DLL 哈希、配置、宿主和版本；逐键输入验证 TSF，不以粘贴替代。真实验证与故障注入分开记录。
- Android：记录 APK 哈希、设备型号/API/ABI/页大小、词表与配置；安装启用后在外部应用逐键输入。App UI 测试、JNI 集成测试、真实输入宿主三类证据分开。
- 当前未连接 Android 真机；到达设备验收时若设备缺失，明确保留该验收未完成，不能凭模拟器标记完整交付。

### 性能与内存

固定真实主表/英文/拼音词表及宽前缀样本，记录冷加载、逐键计算、JNI 转换、首屏/展开候选、上屏端到端 p50/p95/p99，记录峰值及稳定 PSS、包体和长时间输入的资源增长。

Windows 在相同环境对比基线，持续可复现的退化必须解释并处理后再迁移；手机阈值依据 CP-12/CP-14 的目标设备与首次基线写定，不能先声称“微秒级”或沿用桌面阈值。量测区分 UI/宿主和核心耗时，不能只报告 Rust 检索平均值。

原生库需要检查 ELF 段对齐和 APK 对齐，并在适用的 16 KB 环境运行；只有编译通过或使用较新 NDK 不足以判定合格。

## 8. 回退与范围控制

- 每项实现独立可审查，不自动升级不相关依赖、改变配置含义或修改 TIP 生命周期。
- 兼容映射作为迁移入口保留到 Windows 全部调用迁移并通过 G2；不长期维护第二套检索/状态机。
- 新旧逻辑的差分运行只在测试/专用影子验证中执行，新逻辑不得在真实宿主重复写入。
- 若发现既有非 BMP 替换范围、无效配置等缺陷，记录复现和影响，以独立修复任务处理；不得为保持测试数量伪称其已解决。
- 回退某一步代码后，旧 Windows 构建仍能读取原数据；本系列不做无法回退的用户文件迁移。
- Android 新能力只有通过对应契约才启用；不通过在 Kotlin 复制规则绕过共享接口缺口。
