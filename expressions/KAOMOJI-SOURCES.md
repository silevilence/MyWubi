两来源接受数据共有 361 个相同输出，最终 **34354 个不同输出**。合并的是完全相同的 Unicode 字符串，不把空格、全半角、组合符号差异当作重复。547 个不同类别标识全部有中文映射；重叠分类的中文词合并到同一输出，保留来源及最早出现顺序。

`kaomoji-categories.tsv` 记录全部映射，针对情绪、动物、动作、问候和场景整理中文完整词与同义词。已对照类别名核对语义，并抽查 `sun`、`tsu`、`sarasara`、`kiri` 等歧义类别的原始样本，修正为面无表情、耸肩、消散等。类别只是上游整理的检索线索，不保证分类内每个字符串只表达一种情绪；不同来源的分类可能交叉。

## 无损规则与排除

输出字符串不得 trim、NFC/NFKC 归一化、转义解码或替换字形。反斜杠、内部/首尾空格、罕见符号、组合附加符及全半角全部原样保存。两条都可显示成近似图案的输出仍可为不同变体。

排除条件按下列顺序判断，便于每条记录只有一个可复核原因：

1. 空白输出。
2. 超过 512 个 Unicode 标量值。
3. 含换行、回车或 U+2028/U+2029 的多行艺术字。
4. 含 Unicode Cc 控制字符。
5. 原始字符串含 `&gt;`、`&#x27;` 等完整 HTML 实体残留。未擅自把它们解码成另一串字符；这类记录暂不内置，未来上游修复后可重新审查。

本版本排除 3375 条源记录：3254 条 HTML 实体残留、120 条多行、1 条控制字符；空白及超长为 0。`kaomoji-excluded.json` 逐条保留来源、类别/slug、原始索引、原串和原因；`kaomoji-coverage.json` 汇总每来源、每类别、去重及排除数量。

## 重建与验收

运行 `python scripts/build_expressions.py --check --kind kaomoji` 离线验证源文件哈希、映射完整性和生成结果。Rust 数据测试逐条检查最终字符串确实存在于相应原始来源中、中文触发可达、指定情绪/场景覆盖、整库导出/重载逐码点一致。显示缺字不会成为修改原字符串的理由，字体与真实宿主验收另见 EM-06/07。
